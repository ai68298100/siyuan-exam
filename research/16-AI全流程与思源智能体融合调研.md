## 一、AI 在总定位中的作用

产品定位升级为“AI 贯穿的本地可验证备考工作台”。AI 帮用户把有权处理的资料变成范围、候选题和可复盘学习对象，围绕真实作答提供提示、解释、错因假设与下一行动，并将经过用户确认的理解沉淀到思源。资料整理、作者工作台、练习、错题、记忆、模考、报告、计划和知识写回都需要定义 AI 能做什么、何时做、依据是什么及产物如何使用。

核心目的仍是帮助用户理解、独立解决问题、延迟复测和形成可迁移知识资产。AI 的优先地位体现为共享任务与上下文、就地交互、优质模板和智能体编排；确定性计分、FSRS 调度、作答记录、版权范围以及最终应用动作保持可核查。无 AI、预算用完、不允许外发或离线时，学习/保存/恢复主旅程仍成立。

用户最短路径可以是：“选一份自己的资料→AI 整理范围并给待审题→用户核对→独立作答→提交后按依据讲解→用户确认一个修复行动→延迟复测→写回笔记”。每次 AI 产物必须连接到当前学习目标，避免只有长聊天或持续生成题量。

## 三、思源 AI 的两个接入方向

### 1. 插件调用用户配置的思源模型

现有通道适合按用户触发处理单个任务，前提是思源 AI 已启用且模型配置可用。内核代理不代表本地模型或免费服务，实际请求可能发到用户配置的外部提供商。当前 msg 拼接不能假定具有多角色聊天同等的隔离、结构化响应或原生工具机制；按实际通道探测模板、模态、上下文、流式、取消及成本能力。

### 2. 思源智能体调用小驴考试的业务能力

官方插件 SDK `Plugin.addAgentCapability` 可将本插件能力注册给思源智能体。注册返回能力 ID，不是模型响应或会话；`handler` 处理智能体传入的业务参数。两种接入可以共用任务服务，但注册能力不能被描述为另一种模型端点。

核查基准：本地 `siyuan@1.2.5` 类型已声明接口；官方 v3.8.0 已提供 addAgentCapability，v3.7.3 使用旧 addAgentAction。详细源码固定在 v3.8.6 commit `158812497497c6fa8a6d1031bfa2f025a61ee5c2`。版本标签、源码与类型成立不代替当前宿主实测。

| 注册字段 | 官方契约及设计含义 |
| --- | --- |
| name/title/description | 局部能力名、展示标题和明确用途；描述中写出输入范围、产物和不能完成的操作 |
| inputSchema/outputSchema | JSON schema 约束输入/输出；插件还需检查对象是否真实、目标范围、revision 和引用支持 |
| effects | localRead/localWrite/dataEgress/externalCost 布尔声明；必须如实覆盖读取、写入、外发和费用 |
| actionEffects | 若能力以 action 区分操作，则按 action 声明实际副作用；优先把查询、提案和应用分开 |
| handler(args, app) | 异步返回 result/structuredContent/error，产物进入智能体后续上下文，不提供任意 SQL/路径/内核代理 |
| 返回值与执行实例 | 能力 ID 形如 `plugin/frontend/<编码后插件名>/<编码后能力名>`；调用由当前发起会话的前端实例执行 |

生命周期为：注册→发送 manifest→编译 schema→智能体选择→权限/确认→前端调用 handler→回传→输出验证→继续会话。关闭窗口、重载、卸载或 generation 变化后不能假定原能力仍可执行；跨端/无界面支持需逐项验证。

### 3. 宿主确认、业务批准与恢复

官方能力策略支持禁用、确认、允许及会话允许。默认有写入/外发/费用风险时需要确认，未明确 effects 也默认需要确认；用户策略可能免确认，因此不能承诺“每次执行都弹宿主确认”。插件要另外核对所选项目、实际材料、目标 revision、变更 diff 和允许动作，生成提案与应用分离。

浏览器能力没有自动内核快照，不能把宿主确认等同事务/撤销保护。超时、取消或输出 schema 失败可能发生在执行之后，源码存在 ExecutionUnknown 语义并禁止自动重试；应用动作应具备 taskId、幂等回执、恢复核对与明确撤销范围。已经发生的外发/费用也不能因 UI 取消而宣称撤回。

`localRead:true` 不表示整个会话本地：返回的 result/structuredContent 会进入智能体工具结果，思源若走外部模型，仍要按总上下文确认发送范围。因此只读摘要也要最小化，不能把全题库和个人答案默认为安全工具输出。插件可约束自己的能力，无法全面控制宿主其他功能或用户在外部工具获取答案。

## 四、首批能力目录与编排边界

以下局部名称是拟议业务目录，不是现有已注册工具或官方 SDK 字段：

| 能力候选 | 输入与产物 | 执行边界 |
| --- | --- | --- |
| project.summary | 用户选中项目/时间窗→确定性统计、范围/来源缺口摘要 | 只读，工具输出最小化；不默认包含题干和个人答案 |
| question.propose | 用户允许资料/目标→待审候选题与来源 | 有模型调用/外发/成本时如实声明；不直接入库 |
| practice.explain | 已提交题目/获准依据→讲解或错因假设 | strictMock 期间禁用题目级调用，来源未核保留争议 |
| study.proposePlan | 统计/分钟预算/允许行动→计划草稿 | 不改到期、原计划、成绩；缺上下文时补问 |
| knowledge.proposeWriteback | 选定复盘/目标笔记→diff 草稿 | 用户反思与 AI 解释分开，目标范围受限 |
| draft.apply | 用户已批准的提案 ID/target revision→幂等回执 | 写入与副作用明确；版本冲突或执行未知先核对，不能盲重试 |

先做只读摘要和一条带待审产物的闭环，评测、保存和恢复成立后再扩展写入能力。能力执行复用普通 UI 的校验/提案服务，不另建“智能体入口可绕过”的执行链。智能体只按用户本次目标选择步骤，不后台长期自主运行或扫描整库。

## 五、总层面与细分模块的 AI 任务矩阵

| 模块/目的 | 用户触发与必要上下文 | AI 产物及确认方式 | 成功依据 |
| --- | --- | --- | --- |
| 输入整理 | 用户选文件/错误行/原页 | 字段边界、OCR 歧义、材料归属修复候选；对照原件确认 | 少错误、缺失可见；缺答案不补造 |
| 范围与大纲 | 用户提供课程目录/规则/题库摘要 | 主题树、覆盖缺口、映射候选 | 每项回到来源，题量不变掌握度 |
| 命题 | 用户资料、认知目标、题型和预算 | 原创候选/误解型干扰项/引用；进入待审 | 人工正确性、唯一性、可诊断性与出处 |
| 审题与作者 | 候选题/完整原分片/规则版本 | 先独立作答再对照、问题清单、修订 diff | 误放/误拒、依据一致；模型一致不视为真值 |
| 练习提示 | 未提交题、当前步骤、帮助层级 | 一次一层提示，不传隐藏答案 | 不泄题、用户能继续；记录受助条件 |
| 苏格拉底陪学 | 用户自述与有限对话 | 一轮一个问题/更小步骤/退出选择 | 问题对应真实思路，不预设用户错误 |
| 提交后讲解 | 已提交、答案核验/引用状态 | 关键步骤、逐项依据、下次检查点 | 引用支持结论，争议保留，用户可自我解释 |
| 主观评阅 | 答案与用户/教师 rubric | 分项证据、建议分、修改方向；人工确认 | 未评/部分/无法判断分开，分值边界可查 |
| 错题诊断 | 用户步骤/耗时/信心/提示与复测 | 错因假设、澄清问题、一个验证行动 | 不把一次错误归为粗心，后续可验证 |
| 闪卡与复测 | 已核资料、用户反思/卡类型、到期摘要 | 拆卡/最小卡/复测条件提案；先展示负荷 | 卡面不泄题，AI 不建卡评级或接管 FSRS |
| 模考 | 交卷后冻结卷、时间、标旗/改答 | 策略与耗时复盘，不改旧卷/成绩 | 条件可复现；交卷前不调用教学 AI |
| 报告 | 确定性指标/分母/时间窗/缺失状态 | 解释趋势与不确定性、下一行动 | 不编分、不预测排名/通过，低样本明确 |
| 计划 | 用户分钟预算、范围/考期/已允许行动 | 容量内计划/缩减/延期比较；批准后应用 | 用时不超预算，每项有完成定义 |
| 知识写回 | 用户反思、获准引用、目标块版本 | 事实/AI 补充/用户原话分层笔记草稿 | 用户可改、可拒绝、可撤销，原作答不覆盖 |
| 生态联动 | 用户所选素材与已探测系列契约 | 拾遗资料→题源提案；今日行动→打开/打卡/闪卡提案 | 实际支持与手工回退明确，不伪造完成/评级 |
| 帮助与退出 | 用户主动选脱敏回执/偏好/迁移范围 | 只读恢复建议、证据/模板迁移清单 | 无密钥/全库读取，不自称修复，删除边界准确 |

每个模块都需同时设计“使用 AI”“需要用户补什么”“AI 不可用时如何完成”，避免把 AI 缩成独立页面或把所有动作交给对话。

## 六、优质内置提示词的具体交付

新建 [docs/18](../docs/18-AI智能体与提示词模板规范.md)，提供固定契约、输入/结果对象、19 类任务目录、13 个完整任务正文、10 类考试/学科/媒体叠层和原创正反例；新增资料片段学习模板衔接 [research/17](17-付费资料与本地网盘媒体联动调研.md)。正文可评审但尚未替换源码中的运行时提示词。

采用“固定契约→任务正文→考试叠层→用户偏好→schema”组合，通用命题、提示、rubric 和计划任务在不同考试复用，考试叠层提供具体范围/版本/步骤约束。学校按学段与学科；CET/KET 按技能/任务/音频；法考按年度/法域/生效日；CPA 按准则/税法/量纲；CFA 按 Level/curriculum/vignette 构答与 PSM 分层。

模板质量取决于必要输入、证据不足的处理、可核对引用、产物能否接上行动，以及人工评测。单纯堆角色形容词、要求“严谨”、增加二遍或高自信值不能证明质量。用户可以修改表达与目标，不能通过 prompt 覆盖模式、权限或写入约束。

独立审题采用两个输入阶段：第一阶段不提供候选答案/解析，输出受支持的答案和问题；第二阶段再对照。提示/苏格拉底同样在未揭示时排除答案和解析，还要检查检索/兄弟题/旧对话的泄露，输出也可能暴露推断答案，须有边界评测与正式揭示路径。

## 七、思源专用技能作为可选载体

官方思源智能体使用带 name/description frontmatter 的 `SKILL.md`，先发现技能描述，再按需加载正文/资源。v3.8.6 源码中工作区技能位置为 `data/storage/ai/agent/skills/<名称>/SKILL.md`；用户技能来自 `~/.agents/skills` 的启用项，工作区同名技能优先。

内置任务模板先由插件版本管理；后续可提供用户主动安装/更新的“小驴备考”思源专用技能，让智能体理解能力目录、题源/独立作答/审校规则与任务选择方式。安装/更新需展示位置、同名冲突和 diff，不自动覆盖用户技能、全局 AGENTS.md 或模型配置。本轮只规划，不写入这些目录。

技能文本是任务指导，权限由宿主与插件工具服务执行；技能缺失不影响普通模板入口。思源技能与本次 Codex 会话可用技能是不同运行环境，不能混用发现/执行机制。

## 八、知识产权、隐私与学习证据

延续用户要求：插件提供功能、方法和原创模板，材料由用户上传/主动选择。AI 只处理用户有权处理和允许外发的内容；付费访问不自动允许复制/外发，AI 改写不消除原来源限制。指针伴学仅使用获准元数据与个人笔记，不能让智能体根据 URL 自动取题。题目、解析、媒体、识别文本与 AI 衍生物分别保留权利链。

工具返回数据也可能外发，来源卡与授权证据应保留本地，仅向模型提供必要范围/状态和获准片段。日志默认任务/模板版本、sourceRef/hash、状态与用量，完整诊断由用户选范围和期限。保存、共享、AI 外发、私人备份分别判断用途；模板示例和评测素材全部原创或明确授权。

AI 提示、讲解、脚本阅读与协作完成均是帮助暴露，不能伪装为独立作答或官方成绩。AI 建议分、错因与掌握解释保留为候选，不改原答案/历史、FSRS 评级或权限。笔记写回区分用户原话与 AI 解释，AI 不替用户宣布“我已经理解”。

## 九、运行、验证与下一批选择

新增任务按能力建预算：输入/输出字符或 token、调用数、端点、并发、超时、失败用量、人工校对时间。分片/缓存身份含来源/题目 revision、模式、模板版本、模型/端点、权限与必要偏好，防串题、串答案或把旧权限成果当新授权。缓存仍遵守许可期限，不能用本地副本绕过在线访问限制。

评测至少覆盖引用支持、事实/数值正确、单选唯一性、hint 隐性泄露、错因证据、rubric 分项和上限、容量内行动、schema/动作/目标检查、取消/执行未知和恢复。使用人工金标准，不用模型自评分替代；尚未执行模型评测，不能发布准确率或教学效果数字。

可靠性基线继续优先闭合。AI 优先纵切为：用户资料→有证据的待审题→独立答→提交后讲解→一次修复行动/知识写回，并通过思源智能体只读摘要或提案入口复用；进一步上线具体应用能力需完成权限、幂等、恢复与真机前端验证。77 条为候选和细化，不是整体开发排期。
