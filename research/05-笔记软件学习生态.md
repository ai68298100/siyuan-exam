## 一、逐产品/插件深挖

### 1. Obsidian Spaced Repetition（st3v3nmw/obsidian-spaced-repetition）

**定位一句话**：把闪卡与「整笔记复习」直接定义在标准 Obsidian Markdown 里，用 SM-2 / FSRS 调度复习，是「数据全部存在笔记里」路线的标杆（约 2 万+ 星级社区事实标准；README 宣称支持 FSRS 与 SM-2 双算法，仓库 docs 里 algorithms.md 仍写 FSRS "Planned"，文档滞后于主线实现）。

**核心机制详细清单**：

- **卡片存在形式（全部是笔记正文 + 注释，无独立数据库）**：
  - 单行问答：`Question::Answer`（分隔符可配置）；单行双向：`Question:::Answer` 一次生成 2 张「sibling 卡」。
  - 多行问答：`问题行 \n ? \n 答案行`（`?` 独立一行，前后内容可跨行）；多行双向用 `??`。
  - 挖空卡：默认 `==高亮==` 即挖空，另支持 `**加粗**`、`{{花括号}}`；`==text==^[提示]` 给挖空加 cue 提示；`==text==[^1]` 经典带序号挖空（同序号合并在一张卡、不同序号拆成多卡）；Generalized Cloze Overlapping 用 `[^ashh]` 这类字母串逐个指定每个删除点是 ask/hide/show，实现渐进遮罩阅读。
  - 自定义 cloze 模式：设置里写 `{{[123::]answer[::hint]}}` 即可模拟 Anki 风格挖空，插件自动生成正则。
  - 卡片富文本完全继承 Obsidian：图片、音频、视频、LaTeX、代码高亮、脚注都能进卡片。
- **多队列/deck 组织**：两种可选模式——
  - 层级标签：`#flashcards`（默认根）+ `#flashcards/子队列/孙队列`，嵌套 tag 自动成嵌套 deck；
  - 文件夹路径：`Folder/sub-folder` ⇔ `Deck/sub-deck`。
  - 单文件多队列：文件内先后出现 `#flashcards/deckA`、`#flashcards/deckB`，标签作用于其后所有卡片直到下一个标签；
  - 单卡多队列：卡片首行写多个标签 `#flashcards/language/words #flashcards/trivia`；
  - 「问题级标签」：标签出现在卡片首行行首时只作用于该卡。
  - frontmatter `flashcards: True / Multi-Line / Reversed` 控制该笔记只解析哪类卡型。
- **复习交互**：命令「Review Flashcards from all notes / in this note」或左下角抽屉列出 deck 树（点击父队列自动含子队列）；Review（只出新卡+到期卡）与 Cram（全量强灌、算法完全忽略）双模式；卡片操作条 = Edit / Reset（间隔回 1 天、ease 回默认）/ Info（查看调度数据）/ Skip / Delete；键盘 `Space/Enter` 显答案、`0`=Reset、`1/2/3`=Hard/Good/Easy。
- **卡片上下文自动生成**：复习界面标题显示 `笔记名 > 一级标题 > 二级标题`，卡片天然带着「来源定位」——这是卡片与笔记结构结合的关键设计。
- **Statistics 面板四维度**：Forecast（未来到期量曲线）、Intervals（复习间隔分布）、Eases（ease 分布）、Card Types（New / Young / Mature，Mature = 间隔 >1 个月）。
- **数据存储设计（本调研核心关注点）**：
  - 卡片调度信息 = 卡片文本后的 HTML 注释 `<!--SR:!2024-08-16,51,230-->`（日期,间隔,ease）；默认放下一行，可选与卡同行（避免破坏列表结构与格式化）。
  - 整笔记复习的调度 = YAML frontmatter：`sr-due / sr-interval / sr-ease`。
  - 用户选项与「bury sibling 今日已审列表」存插件 `data.json`；社区长期争议的「集中式单一调度文件」（issue #162）至今未实现——纯笔记存储路线的代价。
- **整笔记作为卡片**：`#review` 标签 + 侧栏 Notes Review Queue 按到期排序；复习后执行 `Review note as Hard/Good/Easy` 打分。面向「论述/原理类内容」而非碎片事实。
- **算法与双链的独特融合**：SM-2-OSR 变种会用 PageRank 计算笔记重要性、按反向链接数加权初始 ease（`initial_ease = (1-link_contribution)*base_ease + link_contribution*average_ease`），即「被越多笔记链接的核心概念越受重视」；另有防撞车 fuzz 抖动。
- **卡片维护**：删卡 = 删文本+调度注释；用 HTML 注释包住卡片即临时忽略；RTL 语言可 frontmatter `direction: rtl`。

**值得偷师的具体细节**：

1. 「调度信息以隐形注释内联在卡片旁」→ 思源对应物是**块属性 custom-attr**（`custom-sr-due` 等），同样实现「数据即笔记」，但比 HTML 注释更结构化、可 SQL 查询。
2. 卡片上下文标题 `笔记名>标题>块`：刷题界面每道题显示来源路径并可点击跳回原文——双链结合最低成本高收益的做法。
3. Sibling 卡 bury 机制：同一文本衍生的多张卡一天只出一张，防止互相提示答案——挖空题/多空填空题必备。
4. Cram 模式与 Review 模式分离：考试冲刺场景必需。
5. 统计面板的 Forecast / Intervals / Eases / Card Types 四图是 SRS 统计的通用范式。
6. 复习操作条的 Reset/Info/Skip 全套小操作。

**明确不借鉴的部分及理由**：

- 调度信息写进正文 HTML 注释：可读性差、非结构化、外部工具解析痛苦、格式化器易破坏；思源有原生块属性，没必要沿用。
- 「整笔记当卡片」的 `#review` 队列：与考试刷题场景弱相关，优先级低。
- SM-2-OSR 的 PageRank 加权：实现复杂、收益存疑，思源场景用 Riff 内核自带 FSRS 即可。

### 2. Obsidian CBT Exam Simulator + FlashQuiz（nazdridoy，两个配套项目）

**定位一句话**：CBT Exam 用纯 Markdown + 人类可读标记语法在 Obsidian 里跑「带计时、导航、判分、历史」的机考（Computer-Based Testing）；FlashQuiz 是把同一份题库静态渲染成可折叠学习笔记的伴侣脚本——一份题库两种用途。

**核心机制详细清单**：

- **题目存在形式（普通 .md 文件 + 行首标记）**：
  - 七种题型标记：`@mc` 单选、`@sata` 多选、`@tf` 判断、`@fib` 填空、`@match` 配对、`@sa` 简答、`@la` 论述。
  - 题号强制以 `1)` 或 `2.` 开头，插件按序号自动排序；选项用 `a) b) c)`；答案行用 `= a`、`= a, c`、`= true`；配对题 `Tokyo | Japan` 每行一对；空行或下一个标记分隔题目。
  - 题干与选项完整支持 Markdown + LaTeX（MathJax）。
  - 示例：`@mc 1) Calculate the force if $m=5kg$...\na) $10N$\n...= a`。
- **配置全在 YAML frontmatter**：`quiz-title` / `time-limit`（分钟）/ `pass-score`（及格线 %）/ `shuffle` / `show-answer: true`（开启即变闪卡模式，答题即翻面）/ `exam-range: "1-20, 50-"`（**按题号区间抽题组卷**，支持 `"-10, 20-30, 50-"` 这类多段语法）。
- **考试交互**：以原生 workspace 标签页打开考试界面：集成倒计时（到点自动交卷）、Question Navigator 题目导航格、**Mark for Review 黄旗标记**（考试中标记待回头题，复习时保留）、提交后 Results Dashboard（accuracy / points / time 三指标）、逐题复习时绿/红颜色导航、一键 Retake、随时 Quit。
- **考试历史**：每次尝试写入 sidecar 文件 `{exam-title}-history.md`，可回看历次成绩。
- **Adaptive Study Mode（自适应学习）**：分析历史数据找出你做错/挣扎的题，按「可提升 vs 已掌握」比例（默认 70/30）组织一轮针对性练习——错题驱动的弱项训练。
- **生态位互补**：FlashQuiz 脚本（python flashquiz.py in.md > out.md）把题库渲染成折叠 callout 静态学习卡；与 CBT Exam 共享同一份 FLASHQUIZ_SPEC 格式规范——「同一题源，考试态与学习态分离」。
- **周边**：`vce2flashquiz` 工具可把 VCE 考试引擎文件直接转成本格式（外部题库导入的桥）。

**值得偷师的具体细节**：

1. `exam-range` 序号组卷 + `shuffle` + `pass-score`：一份题库切出模拟卷/章节卷/随机卷，实现成本极低、价值极高。
2. Mark for Review：机考标配交互，模考功能不可缺。
3. `show-answer` 开关让同一份数据在「考试模式」与「闪卡模式」间切换——小驴考试「刷题 vs 背题」双模式可直接复用这个思路。
4. sidecar 历史文件按试卷分档存储考试记录。
5. Adaptive Study 的「可提升/已掌握混合比例」参数化设计。
6. 一份人类可读的题库格式规范（FLASHQUIZ_SPEC.md）作为插件间互操作契约。

**明确不借鉴的部分及理由**：

- 历史记录用 sidecar .md：Markdown 不适合存大量结构化作答记录；思源里用独立 JSON（saveData）或属性视图更合适。
- 行首 `@marker` 裸文本语法：对思源而言，块属性 + 块类型（或代码块）更贴合块编辑器模型，且避免与正文冲突。
- FlashQuiz 的 Python 脚本链路：思源插件应全部内置完成。

### 3. Logseq 卡片系统（官方 docs：Flashcards / Cloze）

**定位一句话**：大纲块级闪卡——给任何 block 加 `#card` 或 `[[card]]` 即成卡，调度数据以**块属性**形式长在卡片块上，复习队列可用查询语法任意切分。

**核心机制详细清单**：

- **卡片存在形式**：block 尾加 `#card`（或 `[[card]]` 页面链接）；右键 bullet → "Make a Flashcard" 即自动补标签；"Preview Card" 可单独预览。卡片就是普通大纲块，子块成为答案内容。
- **调度数据 = 块属性（长在卡片块上）**：`card-last-interval:: 28.3`、`card-repeats:: 4`、`card-ease-factor:: 2.66`、`card-next-schedule:: 2021-11-08T...`、`card-last-reviewed:: ...`、`card-last-score:: 5`——基于 SuperMemo SM-5 变种，评分四档 Again / Hard / Good / Easy（Mochi 出品团队血统）。
- **Cloze**：`/cloze` 命令插入 `{{cloze 内容}}`，一块可含多个 cloze（各出一张卡）；支持 cue 提示：`{{cloze red \\ color}}`（`\` 后为提示语）；点击即可展开/折叠，非复习态也可当折叠内容用。
- **队列切分 = 查询驱动**：`{{cards [[某页面]]}}` 只复习与该页面相关的卡；`{{cards (not [[页面]])}}` 排除式复习；查询可钉在右侧栏 Contents 页常驻——「按笔记/主题切复习队列」而不是靠标签层级。
- **入口**：左侧栏 Flashcards 标签页全局复习；快捷键 `t c`。
- **周边**：调度属性直接可见在大纲里（可折叠）；另有 srs.edn 等内部状态文件；第三方 NeuraCache 可把 Logseq 卡片外流到手机复习。

**值得偷师的具体细节**：

1. **调度数据存块属性**——与思源块属性模型完全同构，是小驴考试题目数据形态的最佳参照（题目 ID/题型/答案/统计全走 `custom-*` 属性）。
2. **查询式子队列**（`{{cards [[页]]}}`）→ 思源对应 SQL 查询块动态圈定「某一专题/某一错题集合」的刷题范围，比静态文件夹灵活得多。
3. cloze 的 cue 提示语法（答案 + 回忆线索分离）。
4. 卡片即大纲块：答案可以是任意嵌套块，天然支持复杂结构答案。

**明确不借鉴的部分及理由**：

- 调度属性裸露在大纲正文里污染阅读（Logseq 靠折叠缓解）；思源块属性默认不进正文，无需处理。
- Logseq 无测验/模考/错题概念，纯 SRS——刷题侧没有可借鉴对象。
- SM-5 自研调度：思源内核已带 FSRS（/api/riff/*），直接对接。

### 4. Notion 学习模板与 Notion→Anki 桥接生态

**定位一句话**：Notion 没有原生 SRS/测验能力，生态用「数据库模板模拟调度」与「外流 Anki」两条腿走路——恰好反证了笔记平台缺学习引擎时生态会怎么补位。

**核心机制详细清单**：

- **闪卡模板（如官方市场 Flashcards Template，4.65 分/29 评）**：
  - 形态 = 数据库：每行一张卡，字段含 正面/背面/难度/下次复习日期/间隔/ease/复习次数 等；SM-2 算法用**日期属性 + 公式属性**模拟「今天该复习哪些卡」的视图过滤。
  - 用户案例：药学卡片、科学测验、语言学习；配合 dashboard 页面（今日到期视图 + 统计）。
  - 题库数据库模板同构：题目/选项/答案/解析/科目/难度/错题标记字段 + 按科目/错题的多视图。
- **Notion→Anki 桥（重头）**：
  - 2anki.net：官方 Notion connection 认证；把 toggle 块/表格/数据库在几秒内转成 Anki 牌组，主打「proper cloze、atomic cards、正确笔记类型」，还支持 PDF/Markdown 输入；免费开源。
  - Notion2Anki.com：富文本页面转卡，保留公式/图片/音频/格式。
  - AnkiWeb 附加组件 "Notion Toggles to Anki"（id 576859862）：Anki 端拉取 Notion toggle 树。
  - NotionBackups 免费转换器：公开 Notion 页面 → .apkg / CSV，可再导 Quizlet/Mochi。
  - CSV 路线：把 Notion 题库数据库直接导 CSV 进 Anki（StudyCards AI 教程），适合考试题库数据库形态。
- **共同本质**：Notion 数据库的 toggle/行 = 卡片或题目，块层级/数据库字段 = 卡片结构；所有桥都在解决「结构化映射 + 富文本保真」两件事。

**值得偷师的具体细节**：

1. **「题库 = 数据库表」的字段设计**：题目/题型/选项/答案/解析/难度/科目/来源/错题次数——思源原生数据库（属性视图）可以直接承载，且支持与知识笔记页双链关联。
2. **导入桥是刚需**：考试用户手里是现成题库（Word/Excel/PDF/VCE/Anki 包），「外部题库格式 → 笔记内题库」转换器的优先级高于一切花哨功能。
3. 题目页 ↔ 知识页双向关联：Notion 模板普遍用 relation 字段连「题目→考点/课程」。
4. dashboard 式入口：今日到期 / 错题 / 各科目进度多视图并排。

**明确不借鉴的部分及理由**：

- 用公式属性模拟 SRS 调度：脆弱、慢、不可靠；思源有 Riff/FSRS 内核，绝不重造。
- 外流到 Anki 的路线本身：小驴考试要「在笔记内闭环」，但**要吸收其导入侧**（apkg/CSV/Markdown 解析作为导入源）。

### 5. 思源集市：知了·RecallGen（Solathis/siyuan-recallgen，v0.1.0，0 星，1.4 万次安装）

**定位一句话**：AI 出题 → 内置答题面板 → 本地+AI 判分 → GitHub 式热力图复盘的「从笔记生成试卷」插件——离题库刷题最近的原生竞品之一，但方向是 AI 生成而非既有题库导入。

**核心机制详细清单**：

- 题目来源：选中块 / 文档 / 笔记本 / 日期范围（"今日笔记"、"最近 N 天"），调 AI 生成 6 种题型（单选/多选/填空/判断/主观/编程），1–50 题，难度配比可调，还有 0–50% 「超纲比例」滑杆让 AI 出笔记外关联考点。
- 三角色 AI 架构：Generator(temp 0.7) → Reviewer(temp 0.3) 审查不合格题回炉重造（保题 ID，最多 3 轮）→ Grader(temp 0) 判主观题+弱点分析+答疑 chat；支持 OpenAI Chat/Responses、Anthropic Messages 三协议、JSON Schema 强约束、走思源 forwardProxy 免 CORS。
- 答题面板：自定义 addTab 单页全卷 + 进度条；编程题内嵌 CodeMirror 6；主观题 Markdown 编辑器；可选倒计时自动交卷；800ms 防抖自动保存进度、关页可续答。
- 判分：客观题本地判定（多选排序比较、填空去大小写多答案），主观/编程 AI 打 0–100 分+评语；结果面板 3 tab（题单含正确答案/解析/评语、AI 弱点分析、学习建议）+ 全卷 AI 追问。
- 数据落地：成绩存 `recallgen-scores.json`（saveData），53 周×7 天热力图、按日聚合可配、历史回放；**"只保存错题（<60 分）"可把题目用 IAL 标记写回思源文档**——错题落笔记的最直接实现。

**值得偷师**：错题（低分题）一键写回文档；答题进度可恢复；客观题本地判、主观题 AI 判的分流判分；热力图打卡维度。
**明确不借鉴**：以 AI 生成为唯一题源（考试刷题需要确定性的既有题库）；AI 三角色审查循环的复杂度先不必。

### 6. 思源集市：Damophus（HibernalGlow/siyuan-damophus，v0.8.0，1 星，57 万次安装，2026-09 活跃）

**定位一句话**：明确标注「自用」的思源增强插件，其中 `lets-question-bank` 模块实现了**扫描→索引→练习→会话恢复→模拟考试→学习报告**的完整本地题库链路，是目前集市上与小驴考试重合度最高的项目。

**核心机制详细清单**（题库部分）：

- **题源 = Markdown + IAL**：题干、选项、答案、解析、专题边界全存正文与 IAL 块属性，附**稳定题目 ID**；插件承诺不改写正文；扫描前先预览「题型推断、冲突、阻塞项、计划写入的 IAL」再确认索引（导入可审查设计）。
- **索引**：题目索引、考点索引、作答记录三个属性视图 + 系统文档自动初始化；旧数据空字段可自动修复。
- **练习**：按文档或任意标题专题递归选范围；筛选维度 = 全部/未做/错题/复习/**Riff 到期**；顺序/随机 + 选项乱序（按原始选项 ID 判题，揭晓后恢复原序）；题型覆盖单选/多选/**不定项**/判断/主观/**共用材料题组**；主观自评、客观自动判 + Again/Hard/Good/Easy 四级掌握评级；答题卡、整卷计时 + 单题计时（看答案暂停计时）。
- **会话恢复**：可暂停/续做/终止的持久化练习会话，逐题草稿自动保存、多窗口写入保护、损坏快照诊断导出——把「做题会话」当一等公民做工程化。
- **模拟考试**：跨文档组卷（来源选择、规则/学科/年份/抽题模式、余量放宽、蓝图保存）；考试工作台含题量/时长/评分模式（**法考评分 / 严格一分**）、允许提前看答案开关、超时自动交卷、成绩结果页。
- **学习报告**：7/30/90 天或全范围：作答覆盖、客观正确率、趋势、分类分布、薄弱题目、最近作答。
- **考点关系（双链结合的亮点）**：题目块与考点笔记块下方**虚拟渲染**考点与关联题目（三种来源渲染模式：HTML 解析/原生 Block DOM/可编辑 SQL 嵌入块），不写入任何块；练习中可虚拟展示考点的动图/图片/视频。
- **与 Riff 分工**：Damophus 管题目范围与渲染，思源 Riff 管闪卡到期与评级调度；到期闪卡可映射为题目、评级提交回 Riff、达阈值自动建快捷卡——「题目走自己的作答事件，记忆调度复用内核」。
- **作答记录**：每次评级 = 不可变作答事件（版本化 JSON 导入导出、去重、孤立题报告）；**错题不落独立文档，全部由事件流动态派生**；原文答案遮罩（模糊/实色/下划线三种）不改题源。

**值得偷师的具体细节**：

1. 数据边界四层表（Markdown+IAL 题源 / 题库核心纯 TS / 思源适配器 / 界面）——架构直接参照。
2. 扫描→预览→确认的导入流程与稳定题目 ID。
3. 不可变作答事件派生错题/统计（而非维护可变错题表）。
4. 考点关系「虚拟显示不落盘」的轻量双链方案。
5. 不定项模式（把单选题升级成可多选练习）。
6. Riff 到期题纳入刷题筛选——与内核闪卡体系打通的正确姿势。
7. 法考评分等考试行业化评分规则。

**明确不借鉴的部分及理由**：

- 「自用」定位导致无文档化引导、无市场运营（1 星、无 README 外的官网）；小驴考试要面向大众做易用导入。
- 它不用 AI 判主观题、不做错题文档——这两点恰恰可以是小驴考试的差异化，不必跟随其克制。

### 2.2 对小驴考试的启示

**必须做（赛道入场券）**：

1. 题库以「块 + 块属性 + 稳定题目 ID」存于笔记（参照 Damophus 数据契约与 Logseq 块属性），一切派生数据（作答事件、错题、统计）不污染题源。
2. 题型全集：单选/多选/不定项/判断/填空/简答/配对/共用材料题组（Damophus 题型 ∪ CBT Exam 七题型）。
3. 刷题会话可暂停续做、逐题草稿、多端安全（Damophus 已验证该工程形态）。
4. 错题本 = 不可变作答事件派生视图 + 低分题一键写回文档（RecallGen 补足 Damophus 缺的错题文档诉求）。
5. 题目与笔记双链三件套：答题界面显示来源路径可跳回原文（OSR 上下文标题）、题目↔考点笔记关联（Damophus 考点关系 / Notion relation）、SQL/查询动态圈题（Logseq {{cards}}）。
6. 外部题库导入器：Word/Excel/CSV/Markdown/Anki apkg/VCE 至少占 2–3 个（2anki、vce2flashquiz 证明刚需）。
7. 记忆调度对接思源 Riff（到期题进刷题筛选、评级回写），不重造 SRS。

**改造后做（有原型、需本地化）**：

1. 模考：exam-range 序号/规则组卷蓝图 + 计时 + Mark for Review + 超时自动交卷 + 行业评分模式（法考/百分制）——CBT Exam 与 Damophus 各取一半合成。
2. 统计面板：Forecast/Intervals/Eases/Card Types 四图 + 53 周热力图 + 7/30/90 天报告页。
3. Adaptive Study：按「可提升/已掌握」比例混卷的弱项训练。
4. 背题模式：show-answer 开关让题库在「考试态/背题态」切换 + 原文答案遮罩（模糊/实色/下划线）。
5. 挖空卡与题目互通：高亮/挖空块一键转题目或闪卡（OSR cloze + highlight-cloze 思路，思源块属性实现）。
6. AI 讲解/判分：客观题本地判、主观题 AI 判的分流架构（RecallGen 已验证），但题源保持确定性导入。

**明确不做**：

1. 调度数据写正文注释或裸露在大纲（OSR/Logseq 的历史包袱，思源块属性更优）。
2. 公式模拟 SRS、外流 Anki 为核心（Notion 生态的无奈之举，思源有内核 FSRS）。
3. 重造完整 SRS 算法与闪卡管理工具箱——闪卡增强已是红海（14+ 插件），小驴考试以「题库/考试」立身，闪卡只做对接。
4. 在线排名/社区/账号体系（Damophus 明确不做，本地优先产品共识）。
5. 「整笔记当卡片」复习队列（#review 类）：与考试场景错位，靠考点关联覆盖即可。

### 2.3 思源集市竞品空位分析

**结论先行：「本地题库刷题/模考/错题本」基本是空位，闪卡类是红海。**

- 全量扫描 538 个集市插件，按 题库/刷题/考试/背题/错题/quiz/exam/question/试题/真题/答题 等 20 个关键词去重命中 22 个沾边插件，其中真正做「题库」的只有 2 个：
  - **siyuan-damophus**：功能最完整但自用定位、无市场运营、1 星、不在主流视野；且明确「不使用 AI、不建错题文档」——留下 AI 讲解与错题本两个差异化缺口。
  - **siyuan-recallgen**：AI 生成试卷路线，v0.1.0 早期、0 星，不做题库导入与 SRS。
- 没有任何一款插件覆盖：题库文件批量导入（Word/Excel/apkg/VCE）、模拟考试组卷、行业化评分、错题本沉淀。题库导入+刷题+模考+错题本的完整闭环 = 空白。
- 闪卡侧完全相反：14+ 款插件卷制卡流畅度、遮挡、渐进阅读、调度增强，且 sy-progressive/tomato/recite 三款 300 万+ 下载的工具箱已内置闪卡功能。再做一个「闪卡增强」没有生存空间；做「闪卡与题库互通」则是无人区。
- 空位风险提示：Damophus 若从自用转向上架推广，是唯一可能的正面竞争者，需跟踪其 release（2026-09 仍活跃）；其「不做 AI、不做错题文档、不做在线功能」的自我设限是小驴考试的天然差异空间。
