## 2. 需要先处理的事实

### 2.1 文件入口与原生题库包

**已复现：标准 XLSX 经过当前入口的文本解码后无法正确读取。** `PracticeTab.svelte:789` 起对 XLSX/XLS/CSV 一律 `decodeCsv(buf)`，随后 `XLSX.read(text, {type:"string"})`。本轮在内存构造带中文的标准 XLSX：原始数组读取得到正确两行，按入口解码再读取报 `Bad compressed size`。`tests/template.test.ts:10` 使用正确的数组路径，解释了模板单测通过而文件入口仍有问题。SheetJS 明确区分二进制数组与文本输入，CSV 的编码探测应作用于文本文件。[SheetJS 读取契约](https://docs.sheetjs.com/docs/api/parse-options/)

最小复现（Node ≥24，项目根目录；通过 `node --input-type=module` 的标准输入执行以下 JS，数据仅在内存中，直接使用当前 CSV 解码函数）：

```js
import * as XLSX from "xlsx";
import { decodeCsv } from "./src/importer/csvDecode.ts";
const wb = XLSX.utils.book_new();
XLSX.utils.book_append_sheet(wb,
  XLSX.utils.aoa_to_sheet([["题干", "答案"], ["中文测试题", "A"]]), "题库模板");
const buf = XLSX.write(wb, { type: "array", bookType: "xlsx" });
const good = XLSX.read(buf, { type: "array" });
console.log("binary read:", JSON.stringify(XLSX.utils.sheet_to_json(
  good.Sheets[good.SheetNames[0]], { header: 1 })));
try {
  const bad = XLSX.read(decodeCsv(buf).text, { type: "string" });
  console.log("UI read:", bad.SheetNames);
} catch (e) { console.log("UI read error:", e.message); }
```

本轮输出：`binary read: [["题干","答案"],["中文测试题","A"]]`；`UI read error: Bad compressed size: 0 != 4022190063`。该结果证明文件读取路径的问题；真实思源界面选择文件仍需按 36-03 验收。

**源码确认：原生包导入协议不一致。** `client.ts:126` 向 `importSY` 发送 JSON `{path}`，界面依赖 `File.path`；SiYuan v3.8.5 端点接收 Multipart 上传文件，文档包与笔记本包还需核对对应入口和目标参数。`app.ts:349` 的成功路径仅清空 `banks`，未发现并持久化新库；`diffBank` 只有纯函数/单测，没有可执行冲突预览。需要先使原生包可导入可练习，再补升级/克隆策略。[SiYuan 导入端点](https://github.com/siyuan-note/siyuan/blob/v3.8.5/kernel/api/import.go)

**源码确认：现有题目读取与更新指纹不完整。** `blockTemplate.ts:94` 固定读回 `analysis:""`；`client.ts:186` 仅用属性与超级块 `content` 构造题目，需用完整块结构验证选项/解析/公式/材料的读写往返。`questionHash` 只覆盖题干和选项，不能直接作为答案/解析/分值修订的版本指纹。原生包重建块 ID 后，还需区分原库升级与独立克隆，防止同一 `qid` 混入两个题库的作答。[SiYuan 原生导入模型](https://github.com/siyuan-note/siyuan/blob/v3.8.5/kernel/model/import.go)、[Anki 稳定身份与更新策略](https://docs.ankiweb.net/importing/text-files.html)

**官方确认：依赖更新不能只运行 npm 最新版升级。** 当前 `xlsx:^0.18.5` 落在两个已公布受影响区间。SheetJS 文档说明 npm 发布源停留在 0.18.5，官方提供 0.20.3 包和固定版本本地保存方案。下一轮评估官方包来源、完整性、离线构建和体积，并重验导入模板；本轮没有升级依赖。[SheetJS 安装说明](https://docs.sheetjs.com/docs/getting-started/installation/nodejs/)、[原型污染公告](https://github.com/advisories/GHSA-4r6h-8v6p-xvw6)、[ReDoS 公告](https://github.com/advisories/GHSA-5pgg-2g8v-p4x9)

### 2.2 作答数据的保存与恢复

**源码确认：卸载先清标记再保存。** `index.ts:170` 先执行 `attempts.dispose()`，其内部清 `dirty`；下一行 `flush()` 因无待保存标记而返回。未满 10 题/30 秒的作答可因此丢失。另有保存并发问题：`attemptLog.ts:119`、`:125` 可重叠保存活数组，响应后无条件清标记，不能确认在途保存期间的新事件已持久化。

**官方契约确认：裸 await 不能建立完整保存确认契约。** `app-runtime.ts:46` 吞读取异常，`:49` 裸 await `saveData`。官方 saveData 通过 fetchPost 的回调兑现；processMessage 仅阻止负 code，正非零 code 仍可能进入回调，而负错误/网络异常可能使外层 Promise 不结算。读取还可能回退到实例缓存。需区分成功、非零响应、无回调超时、文件不存在、读失败与旧缓存，失败后不能把空数据写回。[SiYuan 插件存储](https://github.com/siyuan-note/siyuan/blob/v3.8.5/app/src/plugin/index.ts)、[请求与回调](https://github.com/siyuan-note/siyuan/blob/v3.8.5/app/src/util/fetch.ts)、[响应处理](https://github.com/siyuan-note/siyuan/blob/v3.8.5/app/src/util/processMessage.ts)

**源码确认：设备分片还未实施。** `app.ts:49` 使用固定 `attempts/log`，最终保存为单个 `attempts/log.json` 数组。月份/设备 JSONL、分片枚举和跨端并集是 ADR 0002 的目标方案。事件带 `device/seq/eid` 并不等于多设备写入已经安全。先实测 petal 文件边界与同步钩子，再实施分片及旧数据迁移；同设备多窗口仍需单写协调。[SiYuan 数据变化与加载生命周期](https://github.com/siyuan-note/siyuan/blob/v3.8.5/app/src/plugin/index.ts)、[插件加载器](https://github.com/siyuan-note/siyuan/blob/v3.8.5/app/src/plugin/loader.ts)

**源码确认：续做只保存部分会话。** `SessionState` 不含题库身份、已答历史、重排集合；`PracticeSession.answered/requeued` 在恢复时为空，界面只从默认当前题库补题。要以“已答结果、草稿、游标、反馈、结算、转卡名单一致”验收，而非仅检查能否重新打开。

### 2.3 记忆调度与报告语义

**官方契约确认：评级偏移一位。** `memory.ts:16` 将自评 1–4 转为 riff 0–3，`client.ts:284` 类型也固定 0–3；SiYuan v3.8.5 官方复习按钮将 Again/Hard/Good/Easy 以 **1/2/3/4** 原样提交。已有预检只验证 `rating=3` 能请求成功，不能证明四档映射正确。必须逐档核验卡片状态与到期时间，评级 0 应有明确拒绝语义。[SiYuan 复习界面及请求](https://github.com/siyuan-note/siyuan/blob/v3.8.5/app/src/card/openCard.ts)、[riff API](https://github.com/siyuan-note/siyuan/blob/v3.8.5/kernel/api/riff.go)

**源码确认：选到期题与完成记忆复习是两个状态。** `PracticeTab.svelte:218` 将 due 题放入普通练习，提交只写 attempt；背诵才调用 riff。`reciteAnswer` 把 riff 异常吞掉，界面会继续前进。下一轮明确每种模式的评级/写回策略和失败状态，避免用户以为已完成到期复习。cram 预览保持原调度的边界参照 Anki 的关闭重排语义。[Anki 筛选卡包与重排](https://docs.ankiweb.net/filtered-decks.html)

**源码确认：报告目前是启发式估算。** `report.ts:61` 用平均作答间隔代替稳定性，考点最近一次作答影响整体衰减，没有使用卡片真实 S/D；不足门槛代码为 3 次，而部分文档写 5 题。`app.ts:452` 又把 Hard/“模糊”归为 wrong。需要分开客观判分、成功但费力的回忆、自评和短期重复，报告明确样本/时间窗/估计方法。[Anki FSRS 评级说明](https://docs.ankiweb.net/deck-options.html#fsrs)

**源码确认：错题连对计数未在再次答错时清零。** `replayer.ts:64` 的 active 分支只增加错次。`错→对→错→对` 因此可被累计为两次正确而消灭；应保持在册直到真正连续两次答对。此项需要序列验收，与手动处置覆盖层一起核对。

### 2.5 AI 来源、审核和取消

**源码确认：来源标题不能定位证据，修复会丢失分片归属。** 当前文档只导出 Markdown，生成仍传“粘贴材料”标题；`GenIssue` 未携带原文块/分片，`repairIssues` 与核验取整份材料前 3000 字，后半部分题目可能与错误材料核对。新增来源映射、引用片段校验、源块编辑/删除提示，并让修复使用原始分片。

**源码确认：审核与取消还有持久化缺口。** `approveAi` 成功一次却两次 `aiSaved++`；审核队列没有目标题库和来源快照，存储失败被忽略，开始新生成会清旧队列。`generate` 使用普通 `{aborted}` 标记，在分片间检查但未向 `channel.chat` 传 AbortSignal；分片中途失败也没有逐片保存已完成结果。应以队列状态机、单题幂等批准、分片 checkpoint 与明确取消状态验收。

**源码确认：审题输出与模型自报置信度需要分别校验。** `gen.ts:181` 没有严格要求 pass 为布尔，`pass !== false` 可将缺失字段视为通过；还需验证 id 归属/唯一性及 confidence 的有限范围。当前阈值为 0.85，旧清单写 0.90。**研究判断**：先维护人工标注验收集，统计答案正确/来源支持/歧义与错误放行率，再决定阈值和是否增加独立模型核验；模型自报分数须在本任务样本上校准。[置信度校准原始研究](https://aclanthology.org/2023.emnlp-main.330/)

**源码确认：报告还存在题库/时间范围错配。** `ReportTab.svelte:66` 汇总全部事件，掌握度读取首个题库；`app.ts:299` 的每日战报累积全部历史。新增可见范围、混合事件分母和本地当日定义。进一步记录初答/同会话回炉/提示，采用隔日首次无提示回忆观测，避免即时重复把长期效果推高；Anki 的真实留存口径也限定每日首次复习。[Anki 统计口径](https://docs.ankiweb.net/stats.html#true-retention-table)

## 4. 后续扩展格式的官方核对入口

新格式先定义兼容子集、丢失字段和真实样例，避免仅实现一个解析器就宣称完整支持：

- [Anki 文本导入](https://docs.ankiweb.net/importing/text-files.html)：字段映射、分隔符、文件头、HTML 和重复更新范围。

- [Moodle GIFT](https://docs.moodle.org/en/GIFT_format)：权重、转义、反馈、匹配和数值题先明确支持/拒绝策略。
- [W3C Tabs 模式](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)：方向键、焦点与 tab/tabpanel 关联，Svelte 零警告不能代替键盘/屏幕阅读器验证。

本轮来源以项目官方文档和锁定 `v3.8.5` 的源码为主，未把旧竞品营销描述、模型自报置信度或尚未执行的真机步骤作为完成证据。
