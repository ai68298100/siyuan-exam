## 一、先判断该不该扩展：用户价值与产品边界

小驴考试的核心不是容纳尽可能多的测验控件，而是让用户把可信题源转成可维护的题库，用作答暴露理解缺口，再回到知识笔记与下一次学习。当前已列出不少入口、格式和工程保障；本轮延伸到入口之间容易遗漏的产品机制：题源修订如何影响历史成绩，答对原题能否说明理解，有限时间怎样分配给多个考期，考后如何保留，分享和卸载时用户怎样带走或清除数据。

判断一个候选是否值得进入池子，应先回答四个问题：谁在什么场景遇到困难；为什么现有思源或兄弟插件不能直接解决；该能力是否需要新的数据事实；用户怎样知道结果可信并能撤回。只有说明这些问题后，再讨论界面、模型与接口。

本轮保留 [PRD](../docs/01-功能全景PRD.md) 的本地优先和考试输出定位，不扩展为云 LMS、在线监考、支付系统、内容商城、版权裁决或通用闪卡增强。富媒体题、外部代码任务、带领学习和生态流程可进入研究池，但必须具备独立价值、能力降级和用户确认；不因为竞品具备完整云服务就照搬其账号、权限、通知或分析后台。

主要用户任务进一步分为：

| 用户 | 尚需解决的完整任务 | 成功应如何观察 |
| --- | --- | --- |
| 自主备考者 | 在有限时间中分配多科目，确认哪些内容未覆盖，考后选择保留 | 计划可解释，变化需确认；未覆盖与答错分别可见 |
| 理解型学习者 | 从原题答案回到规则，识别误解，用未见变式验证理解 | 提示暴露、原题重做和变式初答分开记录 |
| 题库作者 | 修订、审校、勘误、交付并保留接收者学习历史 | 发布版本固定，变更预览，引用和历史不静默改写 |
| 本地陪练者 | 分享小任务、人工反馈和共同复盘 | 参加者主动选择，反馈回路可脱离云账号完成 |
| 思源重度用户 | 阅读、批注、知识笔记、练习、复盘之间连续往返 | 同一学习对象拥有稳定身份，不复制出失联版本 |
| 移动或有特殊使用需求的人 | 在软键盘、长材料、低认知负荷、时间适配下完成任务 | 真实设备可完成，功能限制及替代路径明确 |

## 四、学习科学、无障碍和运行环境的机制限制

[Karpicke 与 Roediger 的原始检索研究](https://doi.org/10.1126/science.1152408)支持把检索作为学习动作的研究线索；[Chi 等的自我解释研究](https://doi.org/10.1207/s15516709cog1302_1)及[错题自诊断研究](https://arxiv.org/abs/1602.07253)提示解释自己的推理值得提供脚手架。[例题与认知负荷研究](https://doi.org/10.1016/S0959-4752(01)00017-2)为“完整示例→补步骤→独立作答”提供研究线索，但材料和水平差异需要保留。[迁移与支持条件研究](https://arxiv.org/abs/1603.06647)也说明，完成原题纠正不等于在不同题目中迁移。上述研究不能证明本插件添加按钮后自然有效。因此候选应记录提示暴露、原题重做、独立变式和延迟探针，使用者可跳过，不写“保证记住”“自动掌握”。

顽固错题不能只靠增加权重解决。[Anki 的 leech 处理](https://docs.ankiweb.net/leeches.html)给出改写、补理解、暂缓或放弃等不同路径；迁移到考试场景时还需要题源版本、考试重要性和用户时间成本。自诊断、规则对照、题族与采分点都属于学习支持，不能把一次选错直接判定为误概念，也不能把自评分并入客观考试正确率。

可访问性不仅是 ARIA 标签。本轮补充 [W3C 时间可调整](https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html)、[拖拽替代](https://www.w3.org/WAI/WCAG22/Techniques/general/G219)、[一致帮助](https://www.w3.org/WAI/WCAG22/Understanding/consistent-help)、[输入后可预测行为](https://www.w3.org/WAI/WCAG22/Understanding/on-input)和 [WCAG 2.2](https://www.w3.org/TR/WCAG22/) 的快捷键、交互动画准则；准则的一致性级别不同，不能将全部要求笼统称为 AA 门槛。练习和严格模考要声明不同计时政策，时间适配后的成绩保留条件；拖拽排序提供点击路径，低密度界面保留内容和说明，关闭动画/音效后仍有文字反馈。

[MDN 通知 API](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API/Using_the_Notifications_API)要求先有权限和适当用户动作，移动端构造器能力也与桌面不同。[通知最佳实践](https://developer.mozilla.org/en-US/docs/Web/API/Push_API/Best_Practices)强调实用、及时与退出入口。小驴考试应先实现可静默、去重、可稍后处理的本地提醒中心，再实测系统通知；不能因 Web API 存在就承诺客户端关闭后仍送达。

[BroadcastChannel](https://developer.mozilla.org/en-US/docs/Web/API/Broadcast_Channel_API)仅覆盖同源、同存储分区的上下文，不是跨设备同步；[Page Visibility](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)可帮助识别后台，但不等同于用户学习时间。同步、会话占用、驻留计时和提醒去重应分别建模。[MDN 隐私原则](https://developer.mozilla.org/en-US/docs/Web/Privacy)的数据最小化可以指导出库、展示与分享规则，不能据此保证外发数据可撤回或操作系统截图完全被阻止。

## 七、小驴生态的流程机会与接口现实

本轮从“传一个事件”延伸到“完成一项学习任务”：拾遗中的用户所选材料进入来源预览，考试生成或手工整理候选，审核后回链规则笔记，错题转卡共用思源内核复习，阶段完成可选择写打卡，雷切提供返回今日任务的摘要入口。人脉只有用户明确选择共同学习活动时才有记录交集的意义，不建立题目/错题/成绩到联系人的自动链路。

本地资料需按当前协议成熟度看待：

| 兄弟插件 | 当前可参考的公开资料 | 本轮工作流边界 |
| --- | --- | --- |
| 小驴打卡 | [API v5](../../小驴打卡/docs/api-v5.md)、[生态契约](../../小驴打卡/docs/ecosystem-integration.md) | 可设计达标后单向幂等记录；选择目标、阈值、撤销政策，不把 streak 当掌握度 |
| 小驴人脉 | [BRIDGE](../../小驴人脉/docs/BRIDGE.md) | 共同活动需要明确选择；不传题干、成绩、正文或联系人私有数据 |
| 小驴雷切 | [widget protocol](../../小驴雷切/docs/widget-protocol.md) | 有界摘要和公开命令返回考试，不依赖考试 DOM 或全库扫描 |
| 小驴闪卡 | [扩展架构与数据契约](../../小驴闪卡/docs/14-扩展架构与数据契约.md) | 题卡共存和共享调度可研究；私有 eventBus 不等于已落地跨插件事件 |
| 小驴拾遗 | [DATA-CONTRACT](../../小驴拾遗/docs/DATA-CONTRACT.md) | facade/桥仍需验证；用户所选片段是输入边界，未落地时回退文档选择或粘贴 |

每一步移交应携带稳定 sourceRef、目标身份、返回上下文与有限片段；联动失败不阻断本地练习。该设计细化第 48 组的真实接口和第 60 组的使用流程，不重复创建一个通用自动化引擎。

## 八、分阶段建议与产品验证门槛

1. **可靠事实先行。** 继续以 37–42 组保存、导入、题块读回、riff、真实用时及设备能力为前置。新增数据字段先说明与旧历史、旧题库的关系，不用更多按钮替代基础修复。
2. **先做用户研究与协议样例。** 用自主备考、题库作者、同学陪练三类脚本验证痛点，形成纲要/计划/勘误/出库/分享等纸面样例；优先 51、53、56–58 的最小契约，记录愿意不用哪些能力。
3. **再验证理解闭环。** 在可信题源和来源回链稳定后，选择 52 组自诊断/题族与 57 组勘误各一条完整旅程。观察原题与变式的行为差异，不把新增学习方法直接写成效果承诺。
4. **题型和考试条件按需求解锁。** 54/55 先选有真实样例的数值、听读或 rubric；每增加一种题型，补入库、回读、作答、判分、恢复、导出损失和无障碍旅程。无法本地执行的任务只提供明确外部交接。
5. **生态和陪练最后连接。** 59/60 只基于用户确有的工作流与真实公开契约，伴随撤销、幂等、未安装/旧版本降级；不引入云服务和私有数据依赖。
6. **用证据裁减池子。** 61/62 将场景测试、内容损失、维护成本和替代方案回写 TODO。只有真实旅程、用户价值与可维护契约都成立的候选才进入后续开发批次；可延期、合并或否决，不以 190 条数量作为完成度目标。

本轮交付仅是研究和候选待办。现有 P0 不因研究增量而降级；官方功能页、论文、原型和候选清单都不能替代当前版本的运行证据。
