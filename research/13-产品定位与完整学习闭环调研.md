# 小驴考试 · 产品定位与完整学习闭环调研

## 一、先问“对不对”：插件要解决的真实问题

用户表面上说“我要刷更多题”，实际面对的是四个不确定性：题源是否可信、当前正确率是否被提示或熟题污染、剩余时间应该投向哪里、一次练习的结果能否变成下一步行动。单看题量、连续打卡或一次模考分数，都不能回答这些问题。

因此产品定位收敛为：**思源里的本地优先、可验证的备考闭环与学习证据引擎**。它把可信题源、独立作答条件、理解依据、复测结果和下一行动串成可回溯链；题目仍是思源块，用户可以迁移、审校、写回笔记并在结束后带走全部数据。

“题库长在你的知识库里”继续作为易懂的入口叙事；对用户的产品承诺升级为：**每次练习都留下证据，每个缺口都有下一步**。最终目的不是替用户决定学什么，而是在有限时间内减少盲目刷题，让用户做出有依据的学习决策，并保留退出、迁移和考后复用的自由。

## 二、产品边界与替代方案

自主备考者会在云刷题 App、Excel/日历、Anki 和纸笔之间来回切换。小驴考试的差异是把“题源—作答—复盘—计划—笔记”放在同一份本地数据里，补上各工具之间的结果孤岛；不承诺分数、不爬取最新大纲、不做监考和全服排名。

知识管理者需要从笔记生成题目并保留依据。题目必须拥有来源块、版本和审阅状态，个人反思与作者解析分层存放；AI 永远是候选生成者，不能成为无证据的权威。

题库作者需要发布可维护的内容包。发布前要能 lint、盲答、冻结 revision、脱敏和给出变更影响；接收者可以提出逐题勘误。插件不建设内容市场、支付、DRM 或云端协作。

学习伙伴、教师或家人只需要低数据的异步任务回路：发起者提供范围和完成定义，接收者主动导入并选择性回传证据摘要。该场景不能演化为班级权限、考勤或行为监控系统。

## 三、最终目的拆成可观察的对象链

为了避免继续堆入口，将系统划成六层对象：

1. **目标层**：ExamProject、科目、考期、目标分、考试规则、可用时间和范围快照。
2. **内容层**：Source、Bank、Question、QuestionRevision、Skill、MaterialGroup、媒体及许可证/新鲜度。
3. **行动层**：Session、Attempt、提示/揭示、条件快照、暂停/恢复、纸面或听学状态。
4. **证据层**：答案、判分、置信度、耗时、错因、自我解释、依据阅读、延迟/变式/迁移结果。
5. **决策层**：Plan、Queue、ReviewAction、风险与容量、下一行动及其原因。
6. **迁移层**：Reflection、Export、SharePackage、RevisionImpact、Archive/Exit。

任何新增功能都应至少说明它读写哪一层、如何影响下一层、失败时怎样恢复。没有身份、版本或证据的临时数组不能直接成为报告结论。

可以把这条链画成一个可审计的回路：

```text
Project/Goal → Source → KnowledgeObject → QuestionRevision
     → Session/Paper → Evidence → Decision → Action
                                      ↑             │
                                      └── 新 Evidence ┘
        Package / Provenance 贯穿所有对象，负责交付、恢复和迁移
```

W3C PROV-DM 的 entity/activity/agent、derivation 和 responsibility 适合表达来源转换与审校责任；W3C Web Annotation 的 body/target 与 quote、position、time selector 适合保存页码、块、图片和音频定位；1EdTech CASE 的稳定技能节点可作为考点身份研究参考；Caliper 的 Assessment、Reading、Media、Session、Feedback profile 可帮助整理本地事件词典。它们提供互操作思路，不代表插件已经实现这些标准，也不能替代学习效果验证。

## 四、完整用户生命周期

推荐的主旅程是：设定考试项目 → 选择范围与时间预算 → 导入/创建并审校题源 → 低压力诊断 → 获得今日任务 → 独立作答 → 记录把握度、提示暴露和依据 → 分流为补笔记/重做/变式/暂缓 → 延迟与迁移复测 → 条件化模考 → 读取风险与剩余范围 → 考前冻结与收束 → 考后反思、归档和复用。

首用必须让用户在十分钟内看到一次完整证据闭环；日常入口要减少决策次数；中断、换设备、缺题、导入失败和考期改变都要有可理解的恢复路径。考前阶段减少新内容和炫耀性指标，考后阶段优先保留来源、反思和可迁移知识。

## 五、北极星、护栏和研究指标

本地北极星建议使用“证据闭环完成率”：有目标范围的有效会话中，完成独立作答、记录依据/理解状态并选择下一行动的会话数 ÷ 有效会话数。报告同时显示样本数、提示暴露、原题/变式/条件，不能用题量或单次正确率替代。

护栏指标包括：未完成会话恢复率、导入可修复率、题源带来源比例、决策被用户改写比例、历史成绩被静默改写次数（必须为 0）、导出后可读回比例、AI 候选人工采纳率和本地存储失败恢复率。指标都应可导出、可关闭，不上传遥测。

## 六、产品取舍原则

- 先修复身份、保存、版本和证据，再扩展入口；一个新模式不能绕过既有判分、流水和计划。
- 优先支持“下一行动更清楚”的能力，例如薄弱原因分流、时间容量、来源回跳和复测；题量、徽章和动画只有在不扭曲证据时才增加。
- 复杂题型、教学陪练、家庭协作、本地模型、标准互操作先做样例和成本评估；没有真实需求证据就保持研究项。
- 所有导入、分享、AI 和生态桥都提供撤销、降级、脱敏和退出；不把拟议的小驴插件 API 宣传成已支持能力。
