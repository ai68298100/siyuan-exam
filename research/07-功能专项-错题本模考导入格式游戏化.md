## 专项一：错题本机制

### 1.1 主流做法盘点（带产品例证）

| 产品 | 收录规则 | 移出/消灭机制 | 错因标注 | 导出 |
|---|---|---|---|---|
| 粉笔（公考） | 练习、模考中答错自动收录，入口在「练习→我的错题」 | 重做做对后可移出；支持手动移出「已掌握」题 | 未公开官方细则，社区普遍反馈有"做对但慢/粗心"区分诉求 | 支持导出错题题目（百度经验有图文教程） |
| 猿题库（K12） | 智能练习错题自动整理，按知识点归档 | 间隔重复策略安排错题复习 | 官方未公开文档；同类 K12 产品多提供"粗心/不会/超时"标注 | — |
| 驾考宝典（驾考） | 顺序练习/模考错题进错题统计页 | 反复重做直至通过 | 灯光考试等场景以语音重听代替错因标注 | — |
| 通用刷题软件（保育员等） | 答错自动收录 + 按知识点标签分类归档 | 针对薄弱项发起专项重做，**连续答对后自动移出** | 多数提供手动移出 | 部分支持 |

### 1.2 关键规则与数据结构细节

行业通用约定（综合多来源）：

1. **收录**：默认"练习 + 模考答错即收录"；少数产品只收录练习错题（模考错题单独存"模考错题"）。收录时快照记录：提交的答案、正确答案、用时、所属知识点、错题时间。
2. **消灭周期**：主流是"连对 N 次移出"（N=1~3，常见 N=2），也有产品用间隔重练（1天/3天/7天节点全对才毕业）。
3. **错因标注枚举**（社区通行的三分类）：`粗心`（会做但选错）、`知识不会`（不会做）、`陷阱`（被干扰项迷惑）。标注错因后可按错因筛选重练，如"只重练知识不会的题"。
4. **导出**：导出内容一般是"题干+选项+你的答案+正确答案+解析"纯文本/HTML，供打印。

建议的错题表结构：

```sql
CREATE TABLE wrong_question (
  qid TEXT PRIMARY KEY,          -- 题目 ID
  first_wrong_at INTEGER,        -- 首次答错时间戳
  wrong_count INTEGER,           -- 累计答错次数
  last_streak INTEGER,           -- 当前连对次数（达到 N 则毕业移出）
  reason TEXT,                   -- 错因：careless/unknown/trap，可空
  my_answer TEXT,                -- 最近一次的错误作答快照
  next_review_at INTEGER         -- 下次重练时间（衔接间隔重复）
);
```

### 1.3 小驴考试的落地建议

- 收录默认"练习+模考都收"，提供开关；错题快照必须存**用户当时的选择**而非只存对错。
- 消灭机制默认"连对 2 次自动移出"，错因标注为三分类（粗心/知识不会/陷阱）+ 免标注跳过；"只重练知识不会"作为一键筛选。
- 错题重练直接复用刷题界面，按错因/知识点/时间三维度过滤组卷。
- 导出为 Markdown 到用户笔记本（贴合思源"一切皆块"心智），题干/答案/解析用 callout 区分，便于打印。
- 错题本首页给"消灭进度条"（已消灭/总错题数），把消灭做成可视化成就。

## 专项二：模考/仿真考试设计

### 2.1 主流做法盘点（带产品例证）

- **粉笔模考大赛**：每周固定时间全国同卷开考，考后几分钟内出排名（可按职位、省份维度切分）；官方 Q&A（spa.fenbi.com/page/mokaodasai-qa）明确模考报告入口与考季切换。2025-09 起粉笔出台《规范模考大赛通知》：85 分以上成绩不再对外显示，复盘博主需至少参加一次线下模考且 70 分以上才给授权——说明模考分数已成为强社交货币，平台需防造假。
- **行测智能答题系统**（lyntjy.com 等）：模拟真实行测五大模块（言语/数量/判断/资料/常识），限时倒计时（如 30 分钟/模块）、交卷自动出成绩与分析。
- **答题策略类内容**（闪能/知乎）：分模块涂卡比最后统一涂卡平均节省 3-5 分钟；135 题/120 分钟的节奏安排文章大量存在——证明"涂卡"是真实考试的核心心智，模考产品还原它有真实价值。

### 2.2 关键规则与数据结构细节

1. **计时**：总倒计时 + 分段计时两种。行测标准 120 分钟/130~135 题；分段计时时每模块独立倒计时（如资料分析建议 25-30 分钟），模块时间用完自动跳下一模块（可配置"允许借用"）。
2. **交卷规则**：倒计时归零自动交卷；提前交卷需二次确认；中途退出（切屏）记录切屏次数并在报告展示（防作弊信号）。
3. **答题卡交互**：底部答题卡网格，格子三态——未答（白）/已答（绿/蓝）/标记存疑（黄色小旗）；点击题号跳题；支持"标记"按钮随时标旗，跳题不丢已选答案。
4. **组卷规则**：多题型混合按"模块 × 题型 × 数量 × 分值"配置，例如行测卷：言语 40 题×0.8 分、数量 15 题×0.8、判断 40 题×0.8、资料 20 题×1、常识 20 题×0.5。每个题型可配置来源（真题/模拟/错题重考）。
5. **成绩单维度**（粉笔模考报告实证）：总分、超越率（percentile）、各模块用时与超时题量、"最后 20 分钟动态"（最后阶段做了几题对几题）、知识点掌握度雷达图。粉笔生态中"超过 90% 考生≈国考行测 65 分、95% 更高"是流传的换算基准。

模考成绩单数据模型建议：

```json
{
  "exam_id": "mock-2026-10-01-01",
  "total": 68.5, "full": 100,
  "percentile": 0.91,
  "sections": [
    {"name": "言语", "score": 26.4, "full": 32, "time_spent_s": 1980,
     "time_budget_s": 2100, "overtime_questions": 3, "accuracy": 0.78}
  ],
  "flags_used": 5, "answers_changed": 12, "screen_switches": 2,
  "last_20min": {"attempted": 9, "correct": 6}
}
```

### 2.3 小驴考试的落地建议

- 三种模式分层：**自由刷题（无计时）→ 单卷限时（总倒计时）→ 全真模考（分段计时+答题卡+自动交卷）**，全真模式默认不可回看解析。
- 答题卡三态格子 + 标记旗是必做项（成本低、仿真感强）；切屏计数在思源内以"切换文档/窗口"近似即可。
- 报告页做四件事：总分与超越率大数字、各模块用时条形图（含超时题量）、正确率雷达图、"最后 20 分钟"摘要。
- "模考分数预测"：用历史加权正确率 × 卷面难度系数出预测分（见专项四），并在本地排名中给"历史模考曲线"。
- 防作弊社区化在本地插件场景不适用，但"成绩可分享卡片"（总分+超越率+模块雷达）值得做。

## 专项三：题库导入格式规范

### 3.1 Anki apkg 内部 SQLite 结构（源码实证：ankitects/anki `rslib/src/storage/schema11.sql`）

`.apkg` 本质是 ZIP 包，包含：`collection.anki2`（旧版 SQLite 库）/ `collection.anki21`（新版）+ `media` 文件 + `0/1/2...` 媒体二进制。`media` 是 JSON 映射——源码 `import_export/package/media.rs` 证实为 `HashMap<&str, String>` 经 serde_json 反序列化（键为包内数字文件名，值为真实文件名），新版另有 hash 列表格式。

**schema 11 核心表（逐字段，可直接照抄解析）**：

```sql
CREATE TABLE notes (
  id integer PRIMARY KEY,   -- 毫秒时间戳
  guid text NOT NULL,       -- 全局唯一 ID（同步去重键）
  mid integer NOT NULL,     -- notetype id（笔记模型）
  mod integer NOT NULL,     -- 修改时间（秒）
  usn integer NOT NULL,     -- 同步序号，-1 表示待同步
  tags text NOT NULL,       -- 空格分隔标签
  flds text NOT NULL,       -- 所有字段用 \x1f 连接的字符串
  sfld integer NOT NULL,    -- 排序字段（第一字段）
  csum integer NOT NULL,    -- sfld 的 SHA1 前 8 字节十进制（字段去重键）
  flags integer NOT NULL,
  data text NOT NULL
);
CREATE TABLE cards (
  id integer PRIMARY KEY,   -- 毫秒时间戳
  nid integer NOT NULL,     -- -> notes.id
  did integer NOT NULL,     -- deck id
  ord integer NOT NULL,     -- 卡片模板序号（同一 note 的第几张卡）
  mod integer NOT NULL, usn integer NOT NULL,
  type integer NOT NULL,    -- 0=new 1=learning 2=review 3=relearning
  queue integer NOT NULL,   -- 同 type，另有 -1=suspended -2=buried
  due integer NOT NULL,     -- 复习卡=天数；新卡=序号；学习卡=毫秒时间戳
  ivl integer NOT NULL,     -- 当前间隔（天）
  factor integer NOT NULL,  -- ease 因子 ×1000（如 2500 = 2.5）
  reps integer NOT NULL, lapses integer NOT NULL, left integer NOT NULL,
  odue integer NOT NULL, odid integer NOT NULL,  -- 溢出牌组（ filtered deck ）
  flags integer NOT NULL, data text NOT NULL
);
CREATE TABLE revlog (
  id integer PRIMARY KEY,   -- 毫秒时间戳（作答时刻）
  cid integer NOT NULL,     -- -> cards.id
  usn integer NOT NULL,
  ease integer NOT NULL,    -- 1~4（again/hard/good/easy）
  ivl integer NOT NULL,     -- 本次后间隔（天），学习步长内为负秒
  lastIvl integer NOT NULL, -- 上次间隔
  factor integer NOT NULL,  -- 作答时 ease ×1000
  time integer NOT NULL,    -- 作答用时（毫秒）
  type integer NOT NULL     -- 0=learn 1=review 2=relearn 3=filtered 4=manual
);
CREATE TABLE col (id, crt, mod, scm, ver, dty, usn, ls,
  conf text, models text, decks text, dconf text, tags text);  -- models/decks 为 JSON
CREATE TABLE graves (usn, oid, type);  -- 同步删除墓碑
-- 关键索引
CREATE INDEX ix_cards_sched ON cards (did, queue, due);
CREATE INDEX ix_revlog_cid  ON revlog (cid);
CREATE INDEX ix_notes_csum  ON notes (csum);
```

### 3.2 Aiken 格式（纯文本，仅单选，语法最简）

```
思源笔记的内核是什么？
A. Electron + Node.js
B. Go
C. Rust
ANSWER: B

2+2 等于几?
A. 3
B. 4
ANSWER: B
```

硬规则（MoodleDocs 官方 + 各校指南）：题干必须单行；选项以 `大写字母+点/括号+空格` 开头，选项顺序任意但字母须连续；`ANSWER: X` 行给出答案（X 为字母）；空行分隔题目；支持 `//` 行内注释（A2 版本还支持 `##` 起始的反馈行）。

### 3.3 GIFT 格式（Moodle 全题型，语法示例可直接照抄）

标记符号：`::标题::` 可选题名；`{ }` 包裹答案区；`=` 正确项、`~` 错误项、`#` 反馈；多选答案项前加 `%权重%`（总和 100）；`{FALSE}` / `{TRUE}` 判断；`{#数字}` 填空数值题；`=正确:容差` 绝对容差，`数字..数字` 区间，`=%50%答案:容差` 加权部分得分。

```text
// 单选（含题名与反馈）
::颜色题::法国的国旗是什么颜色？{
  ~红色 #不对
  =蓝色和红色 #正确！
  ~绿色
}

// 多选（权重和为 100）
::多选题::下列哪些是思源特性？{ %50%双链 ~视频剪辑 %50%本地优先 ~云绑定 }

// 判断
 Grant 埋在 Grant 墓里。{FALSE}

// 简答（多个可接受答案）
希腊的首都是？{ =雅典 =Athens }

// 数值题：绝对容差 / 区间 / 加权部分分
圆周率保留三位小数是？{#3.141..3.142}
Ulysses S. Grant 出生于哪年？{# =1822:0 =%50%1822:5}

// 匹配题
::配对::匹配国家与首都 { =法国 -> 巴黎 ~ =德国 -> 柏林 }
```

转义：`\:`、`\=`、`\{`、`\}`、`\~`、`\n`（换行）。

### 3.4 TSV（Anki/多平台通用制表符格式）

```
#separator:tab
#html:false
#columns:题干|选项A|选项B|选项C|选项D|答案|解析
什么是双链？|双向链接|单向链接|标签|文件夹|A|双向链接允许反向索引
```

### 3.5 QTI 标准（1EdTech/IMS）

- **QTI 1.2**：根元素 `<questestinterop>`，题目为 `<item>`，正文在 `<presentation>`，评分在 `<resprocessing>`。
- **QTI 2.1**：题目为 `<assessmentItem>`，命名空间 `http://www.imsglobal.org/xsd/imsqti_v2p1`；测试卷为 `<assessmentTest>`。
- **内容包**：ZIP = `imsmanifest.xml`（资源 type `imsqti_item_xmlv2p1` / `imsqti_test_xmlv2p1`）+ `items/` + `tests/` 目录。Canvas/Moodle/Inspera 等主流 LMS 均以 QTI ZIP 交换题库。

```xml
<assessmentItem xmlns="http://www.imsglobal.org/xsd/imsqti_v2p1"
    identifier="q001" title="示例" adaptive="false" timeDependent="false">
  <responseDeclaration identifier="RESPONSE" cardinality="single" baseType="identifier">
    <correctResponse><value>C</value></correctResponse>
  </responseDeclaration>
  <itemBody><p>题干…</p>
    <choiceInteraction responseIdentifier="RESPONSE" shuffle="true" maxChoices="1">
      <simpleChoice identifier="A">选项A</simpleChoice>
      <simpleChoice identifier="C">选项C（正确）</simpleChoice>
    </choiceInteraction>
  </itemBody>
</assessmentItem>
```

### 3.6 国内 Excel/Word 题库模板通用列约定

综合卷王 SurveyKing、考试星、刷刷题、CSDN 实战文章等，通用列（每行一题）：

| 序号 | 题型 | 题干 | 选项A | 选项B | 选项C | 选项D | 选项E | 选项F | 答案 | 解析 | 难度 | 知识点 | 分值 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 1 | 单选 | … | … | … | … | | | | B | … | 易 | 双链 | 2 |
| 2 | 多选 | … | … | … | … | … | | | ABD | … | 中 | 导入导出 | 4 |
| 3 | 判断 | … | | | | | | | 对 | … | 易 | 基础 | 1 |

约定要点：答案列单选填 `A`，多选填连写 `ABD`，判断填 `对/错`（或 `T/F`、`√/×`）；选项列可留空（E/F 为可选扩展，选项数量不固定是兼容重点）；解析、难度、知识点列可空但列名不可删；Word 导入通常要求题干以 `1.` 编号、选项以 `A.` 换行、答案以 `【答案】B` 标注。

### 3.7 小驴考试的落地建议

- **导入优先级**：Excel/CSV 模板（第一优先，国内用户最多）→ Aiken/TXT → GIFT（全题型）→ Anki apkg（只读解析 notes.flds 按 `\x1f` 拆字段、cards 取题型与复习数据；revlog 可转为本插件复习日志）→ QTI 2.1（低优先，API 类用户）。
- apkg 解析用 sql.js（思源为 Electron 环境，可直接读 SQLite），media 按 `media` JSON 映射从 ZIP 数字文件还原为真实文件名，导入后存入思源 assets。
- 导入向导必须做：列映射预览（用户拖列名到标准字段）+ 前 10 条预览 + 错误行汇总报告（第几行、什么错、原值），而不是遇错中断。
- 内部统一题目 JSON：`{type, stem, options[], answer, analysis, difficulty, tags[], score, source}`，难度统一为 1-5 星存储、显示为 易/中/难。

## 专项四：学习数据报告

### 4.1 主流做法盘点（带产品例证）

- **粉笔**：模考报告含各模块正确率对比 + 知识点掌握度雷达图（k73 产品介绍页证实）；"预测分"基于累计刷题数据（知乎用户实证：刷题 1 万道后预测分与实际接近，预测分比单次模考分更稳）；模考数据以 percentile 超越率定位水平（社区流传：超越 90% ≈ 行测 65 分）。
- **练题狗**：AI 智能推题 = 薄弱知识点 + 顽固错题 + 抗遗忘特训题三路合并。
- **滑记**：AI 抗遗忘算法对"每个用户 × 每个知识点"预测遗忘临界点并推送复习。
- **Anki/FSRS**：把"记忆留存率"做成一等公民的数据模型（见下）。

### 4.2 关键规则与数据结构细节

1. **FSRS 算法（源码实证：open-spaced-repetition/py-fsrs `fsrs/scheduler.py`）**：
   - 21 个默认参数（`DEFAULT_PARAMETERS` 首参 0.212，第 21 参 decay=0.1542），每用户可由优化器个性化。
   - 可提取性（记忆留存率）：`R = (1 + FACTOR * t/S)^DECAY`，其中 `DECAY = -0.1542`、`FACTOR = 0.9^(1/DECAY) - 1`（保证 t=S 时 R=0.9）；S 为稳定性（间隔天数），t 为距上次复习天数。目标保留率 `desired_retention` 默认 0.9。
   - 该公式可直接用于"知识点掌握度随时间衰减"：把知识点聚合后的 S 视作知识点稳定性。
2. **掌握度模型通用设计**（综合各来源）：
   - `掌握度 = 近期答题记录的加权正确率`，权重 = 题目难度权重 × 时间衰减 × 题量置信度（做题少于 5 道的知识点标"数据不足"）。
   - 遗忘衰减用指数函数：艾宾浩斯经典数据（20 分钟遗忘 42%、1 天约 74%），工程上用 `R = e^(-t/S)` 或直接采用 FSRS 公式。
   - `薄弱度 = 1 - 掌握度 × 留存率`，按薄弱度排序推送，即练题狗"薄弱点+抗遗忘"的等价实现。
3. **知识图谱/知识树导航**：粉笔以"知识点树"组织题库（章节→考点→知识点三层即可），报告页从树任意节点下钻到正确率；作业帮类产品将知识点打标视为"教研活"而非算法活——即标签质量决定一切。
4. **分数预测**：粉笔模式 = 累计刷题正确率 × 模块权重 → 预测分，配合模考校准；关键在预测分与模考分分差提示（"预测 69 分，本次模考 58 分，差距主要在资料分析用时"）。

### 4.3 小驴考试的落地建议

- 掌握度三级建模：**题（难度/正确率）→ 知识点（加权掌握度 × FSRS 留存率）→ 模块（知识点聚合）**；公式直接采用 FSRS 的 R 公式，稳定性 S 取该知识点历次"复习间隔"的均值，实现约 30 行代码。
- 报告页四件套：知识点树（正确率染色）、雷达图（模块掌握度）、薄弱 Top10 列表（一键组卷"薄弱专项 20 题"）、分数预测卡（预测分 + 与最近模考的分差归因）。
- 数据不足（<5 题）的知识点显示为灰色而非 0 分，避免误导。
- 所有报告数据落本地 JSON/SQLite，按周快照一次，支持"周报对比"。

## 专项五：游戏化

### 5.1 主流做法盘点（带产品例证）

- **Duolingo（标杆）**：连胜 streak 是核心引擎——设计内核是**损失厌恶**（runwise 增长复盘：简单积分/勋章无效，streak+联赛合计推动活跃用户 +350%）。细节：默认可持有 **2 个连胜冻结**（streak freeze），漏学当天自动消耗保连胜；满 100 天额外奖励 3 个一次性冻结，且每满 100 天补回；冻结可用宝石购买。排行榜采用 **联赛制**（青铜→钻石），每周一个 30 人左右小组，升降级制造流动的竞争感。虚拟货币（宝石/XP）与商城构成闭环。
- **粉笔**：模考大赛是最强的社交化运营——全国同卷、限时开考、考后几分钟出职位/省份排名；2025-09 的"线下模考 70 分以上才授权复盘博主"新规进一步把模考分数变成可验证的社交资产。粉笔早年的"小组"功能（组队刷题、组内榜单）是公考用户留存的重要抓手。
- **争议**：Reddit/UX 社区对 streak/联赛的评价两极——"对学习本身无帮助，只是参与感手段"，存在激励 vs 操控之争。

### 5.2 关键规则与数据结构细节

1. **连胜判定**：以"自然日 + 用户本地时区"判定，完成任一学习行为（答题/模考/复习卡）即保号；冻结数上限 2，自动消耗，满 100 天里程碑奖励一次性冻结。
2. **积分商城**：积分获取（答题量/正确率加成/模考完成）→ 消耗（冻结购买、题目皮肤、AI 讲解次数）——消耗口一定要有真实价值（AI 讲解次数是刷题产品最自然的消耗口）。
3. **排行榜**：周赛制 + 小组制（30 人）优于全服榜（本地插件无服务器，见落地建议）；维度除积分外应有"刷题量/连续答对/消灭错题数"多赛道。
4. **学习时长证书**：累计时长/刷题量里程碑生成可分享卡片（100 天连胜、10000 题、错题消灭 500 道等）。

```json
{
  "streak": {"current": 37, "longest": 52, "freeze_count": 2,
             "freeze_used_today": false, "milestones": [7, 30, 100, 365]},
  "points": 4820,
  "weekly_board": {"week": "2026-W40", "me": {"xp": 680, "rank": 12},
                   "size": 30, "promotion_cutoff": 10, "demotion_cutoff": 25}
}
```

### 5.3 小驴考试的落地建议

- 本地插件无服务器，排行榜做**单机赛道化**：与"自己的历史"比（周环比曲线）+ 与"虚拟基准线"比（如"50 题 Club"梯度），不做虚假全服榜。
- streak 完整移植 Duolingo 规则：2 个冻结 + 满 100 天奖励 + 自动消耗，成本极低、体验成熟。
- 积分消耗口首选"AI 讲解/出题次数"，其次主题皮肤；克制推送——思源场景没有 push 通道，用"打开时的轻提示"替代，避免操控感争议。
- 组队 PK 在本地做"导出挑战码"：生成一周挑战卷（题集+时间），朋友导入后各自作答、互比成绩单。

## 专项六：语音听学与无障碍

### 6.1 主流做法盘点（带产品例证）

- **驾考宝典（官方）**：语音能力集中在三类场景——①灯光考试语音播报（科目三→模拟考试→灯光考试→右上角设置→开启语音播报并可调语速，模拟真实考场的机器读题）；②全局"语音提醒"开关（我的→我的设置）；③3D 练车语音播报。其"听题刷题"并非官方主打。
- **第三方"驾考宝典语音朗读版"类 App**：集成 TTS 引擎实现纯听题模式（自动连读题干+选项，解放双眼），普遍支持朗读倍速调节——说明用户对"听题"有真实需求，官方产品存在供给缺口。
- **无障碍通行做法**：夜间/护眼模式（随系统或手动，降低蓝光）、大字号模式（题干字号独立于 UI 字号缩放）、高对比度主题。

### 6.2 关键规则与数据结构细节

1. **TTS 听题实现链路**：题干 + 选项 A/B/C/D 文本拼接 → TTS 引擎逐段合成 → 播放时高亮当前朗读块；连读顺序 `题干 → 选项（每个前缀"选项A"）→ [等待作答] → 判对错后读"正确答案 B + 解析"`。纯听题模式隐藏题面只留四个按钮。
2. **倍速**：TTS 语速 0.5x~2.0x 连续可调（Electron `speechSynthesis.rate` 支持 0.1~10，实用区间 0.8~2.0）；灯光考试类播报需预置"正常/慢速"两档。
3. **Web Speech API 要点**（思源为 Electron，可用 `window.speechSynthesis`）：Windows 下跟随系统中文语音（如 Huihui/Yaoyao）；`SpeechSynthesisUtterance.rate/pitch/lang` 三参数；长文本需按句切分（超过约 32KB 或引擎超时会中断）；朗读进度用 `onboundary` 事件做逐句高亮。
4. **夜间/护眼**：思源本身有暗黑主题，插件继承 `--b3-theme-*` CSS 变量即可，不自行发明配色；护眼色（豆沙绿 #C7EDCC 类）作为可选叠加层。
5. **大字号**：题干区字号独立滑杆（14~28px），持久化到插件配置；遵循 WCAG 对比度 ≥ 4.5:1。

### 6.3 小驴考试的落地建议

- 听题模式做成"第三种刷题形态"（看题/看题+朗读/纯听题），全用 `speechSynthesis` 零依赖实现，倍速 0.8~2.0x，朗读时高亮当前块。
- 默认朗读含"选项A/B/C/D"前缀与"正确答案是 B"判读，解析默认不自动读（太长），提供逐段点击播放。
- 无障碍三件套直接复用思源主题变量：暗黑跟随主题、护眼豆沙绿叠加层可开关、题干字号独立滑杆（配置持久化）。
- 语音场景优先级：①灯光考试式"模拟语音播报模考"（驾考类题库刚需）②错题重听 ③解析朗读。
