# 小驴考试 · 发版检查清单（docs/23）

> 2026-10-05 建立（七十一批）。适用 v0.7.0 及后续版本；集市（bazaar）上架继续按 7B 门槛暂缓，与本清单无关。

## 0. 版本口径

- 版本号唯一来源：`plugin.json`（思源加载用）；`package.json` 必须同步（release.yml 校验 tag == 两者，漂移会导致发布挂）。
- 守卫已断言两文件一致（check-arch 第 10 项，v0.6.0 曾漂移 package.json=0.5.1 的教训）。
- 版本号变更用 `pnpm update-version`（交互式，两文件一起改）。

## 1. 内容门槛（发版前必须完成）

- [ ] 真机走查：docs/17 人工 UI 步骤剩余项（27/28/36-38）+ 当批新增功能面（资料/笔记/关联/回执/闪卡卡面/考纲对照/AI 家族）
- [ ] `pnpm guard` 八检全绿（types/svelte/i18n/arch/styles/lint/test/perf 口径以 package.json scripts 为准）
- [ ] `pnpm build` + `pnpm verify:package`（白名单 30 文件）
- [ ] 内核在线时 `pnpm smoke`（preflight 17 / smoke-data 6 / smoke-csv 5 / perf-bank）与 `pnpm e2e`（只读走查 0 失败）
- [ ] CHANGELOG 定稿：Unreleased 段落改为版本节（日期+验证状态行），用户可读语言复核一遍

## 2. 发布动作

1. `pnpm update-version` → 选版本（0.6.0 之后为 0.7.0）
2. CHANGELOG：`## Unreleased` → `## 0.7.0 (YYYY-MM-DD)`，补验证状态行
3. commit：`chore(release): 0.7.0`（update-version 已改两文件）
4. `git tag v0.7.0 && git push origin v0.7.0` → release.yml 自动：版本一致性校验 → check → build → zip → GitHub Release
5. 发布后核验：Release 资产 package.zip 可下载、体积合理；`pnpm e2e` 输出「已部署 v0.7.0」

## 3. 已知边界（发布说明应如实声明）
