# 设计评审与优化（2026-10-01）

> 评审范围：定位 / 功能 / 交互 / 与思源融合 / 工程一致性。评审基线：docs/01~04 + 当前脚手架。
> 每条优化标注：**[已修订]** = 已回写到对应文档或代码；**[候选]** = 有价值、待排期确认；**[决策]** = 需要明确产品决策（本文给出建议）。

---

## 一、结论速览（10 条最重要的发现）

1. **[已修订·P0] 多端同步会互相覆盖作答流水**：`data/storage/petal/` 随思源同步走且是整文件覆盖，两端各刷各的题会丢数据。修正：流水按 `月份.设备ID` 分片，各端只追加自己的分片，同步合并=自然并集；错题本等**派生视图从"存储"降级为"本地缓存"**（同步的只有不可变流水与配置，派生视图每端从流水重建）。
2. **[已修订] 交互缺口：题库没有"浏览"的家**。三个 Tab（练习台/模考场/报告）都是"动作"入口，但"翻题库、查某道题、看单题统计"这个第二高频场景没有落点。增补：练习台内分"刷题 / 浏览"双模式，浏览=章节树→题目列表→单题详情（题面/答案/解析/统计/双链/编辑）。
3. **[已修订·P0] 手工录题缺一个表单编辑器**。让用户手写 `{{{row` 超级块 + `exam-*` IAL 门槛过高。增补：斜杆命令与块菜单打开"题目表单对话框"（题型/题干/选项/答案/解析/考点/难度），由插件生成块结构。这是 v0.1 必备，不是可选。
4. **[已修订] 与内置闪卡的共存策略缺失**。题目卡与用户普通闪卡共用内核 riff，思源内置复习面板会把题目卡一起弹出来。策略：独立卡包命名空间 `小驴考试/<题库>/<章节>` 隔离 + README 说明（内置面板按卡包复习，不点我们的卡包即可互不干扰）；插件不写内核全局的每日新卡上限——**期望保留率同理是全局配置，改它会波及用户自建闪卡，设置面板必须加警示，或只做"显示+跳转内核设置"**。
5. **[已修订] 题目渲染方案没定**。刷题 UI 的核心是把题目块渲染成思源观感的富文本（公式/代码/图片）。当前定案：走内核 Lute 渲染端点 `/api/lute/md2html`，将 HTML 放进 `b3-typography` 容器；`/api/lute/md2BlockDOM` 已在 R3 实测确认不存在，最终以 docs/03 §六的在线复核结果为准。
6. **[候选·强融合] AI 应默认走思源内置 AI 配置**。思源 3.8 设置里已有 AI 模型配置，内核提供 `/api/ai/*` 端点——插件直接复用，用户零配置开箱即用；BYO key 降级为高级选项（想要独立模型/温度控制的人）。远期用 `addAgentCapability` 把"给此笔记出题/讲解此题"注册为思源 Agent 能力。
7. **[候选·强融合] 题库管理视图可借力思源数据库（属性视图）**。题目块绑进属性视图（每题一行），掌握度/错次/正确率作为列回写——用户免费获得筛选/排序/分组，且符合小驴管家"台账进数据库"的家族设计原则。作为 v0.2 题库浏览的实现候选（备选=自研浏览视图）。
8. **[已修订] 三套"掌握"规则需要一张状态机**。错题消灭（连对 2 次）、形态升降级（答错 2 次降背诵/背诵 4 连升级）、转卡时机（错 ≥2 次）三个 N 各自为政。定案一条规则链（见 docs/02 附录 A），核心语义：**错题本消灭≠停止记忆**——错题刷熟移出错题本，对应闪卡继续走 FSRS 自然拉长间隔；对用户只讲一个词"掌握度"。
9. **[已修订] 考点标签没有兜底路径**。调研实证"标签质量决定统计的一切"，而用户 Excel 常没有考点列。定案：**章节（文档结构）即兜底考点层级**——题库天然有文档树，统计/掌握度/举一反三全部可退化到章节粒度运行；`exam-kp` 是增强不是前提。
10. **[决策] 与"小驴卡盒"的关系要切开**。小驴考试的记忆功能自包含（cram/统计/转卡只服务题库）；若将来做卡盒，定位改为"思源全局闪卡的统计仪表盘+FSRS 优化器"（服务内置闪卡全家），两者不重叠。建议：考试先走，卡盒无限期后置。
