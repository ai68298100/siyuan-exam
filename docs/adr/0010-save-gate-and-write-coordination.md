# ADR 0010 — 对象级保存确认（SaveGate）与流水写入协调

日期：2026-10-03 ｜ 状态：已接受 ｜ 关联：docs/19 Q2、docs/21 U06、TODO 37-01/02/03

## 背景
持久化散布在多个目标（练习会话、模考快照、行动、映射、AI 队列），此前"是否保存成功"没有统一答案：写入静默失败会被当作已保存；同目标并发写互相覆盖；卸载顺序先 dispose 后 flush 导致最终落盘空转、未落盘事件丢失。

## 决策
1. **SaveGate per-target 状态机**（`core/saveGate.ts`）：每个保存目标独立 `pending → confirmed | failed | unknown`；同 key 在途写入合并；超时（默认 8s）置 unknown——结果未知不冒充成功也不误报失败，写入完成后真实结果覆盖。
2. **流水串行协调**（37-03）：`AttemptLog.flush` 快照写入 + 代次检查——慢写期间追加的事件保持 dirty 并自动补写，恰好一次持久化；落盘失败不清待保存标记（`lastFlushError` 留痕）。
3. **卸载顺序定案**（37-02）：先 `flush()` 再 `dispose()`（清定时器）；反向顺序会让最终落盘空转。
4. **顶栏可见**：`SaveStatus` 组件在练习/模考头部显示 failed/unknown/pending 徽标，点击定位具体目标与失败原因。

## 后果
- 每个入口的"保存了什么、成没成"可回答；跨重载的 SaveGate 状态持久化仍开放（当前为内存态）。
- petal 慢写/失败注入与双窗口并发仍属 TODO 37-01/37-04 真机验收面。
- 会话与模考快照的"随答随存"依赖同键合并语义，未放大写放大。
