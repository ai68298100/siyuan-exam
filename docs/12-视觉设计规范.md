# 小驴考试 · 视觉设计规范

> v5，2026-10-02。依据：[信息架构](10-总体设计与信息架构.md)、[交互规范](11-UI原型与交互规范.md)、[设计套件](13-UI设计套件总册.md)及[分阶段规划](19-待办融合与分阶段执行规划.md)。
> 本文核对本地原型的实际样式与路由，并规定后续视觉验收目标。原型是原创示例与内存状态演示；不代表插件实现或真实学习效果。

## 1. 视觉目的与资产

界面先让用户知道当前目标、作答条件、保存情况及下一操作。资料、题面和个人笔记占主要空间；来源、权限与AI任务状态在需要时可展开核查。视觉层级以文字、间距、边界和明确动作建立，状态不只依赖颜色。

本地原型拆分为三个文件：

| 文件 | 实际职责 |
|---|---|
| [index.html](../design/prototype/index.html) | 页面框架、主导航容器、主题/状态演示工具栏、对话框及状态播报区 |
| [prototype.css](../design/prototype/prototype.css) | 独立原型的深浅主题、版式、控件、响应式与可访问性样式 |
| [prototype.js](../design/prototype/prototype.js) | 15个hash路由、原创题目和模拟交互；刷新重置内存示例 |

原型默认浅色，可手动切换深色。阅读、复习和模考均保留所选主题；专注状态通过收起辅助信息建立。模拟视频画面有自己的配色，原件画面与整页主题各有用途。

主题切换只改变视觉表达，不能改变评分、会话条件、来源许可或任务状态。成功色用于明确成功回执；待审、证据不足、权限受限与来源过期用文字表达，AI自报信心不使用“已核验正确”徽章。

## 3. 文字与信息层级

原型使用系统字体栈：`-apple-system`、`BlinkMacSystemFont`、`Segoe UI`、`PingFang SC`、`Microsoft YaHei`、sans-serif，无外部字体请求。模拟讲义纸页单独使用Georgia/Songti SC/serif，表示原件区域。

| 内容 | 当前原型规格 | 使用原则 |
|---|---|---|
| 页面标题 | 30px/1.4；≤850px为27px，≤600px为24px | 一页一个明确目的，长标题可换行 |
| 区块标题 / 小标题 | 17px/1.6、15px/1.6 | 区分正文层级，避免标题抢占作答空间 |
| 正文 | 14px/1.7 | 资料、状态与行动说明保持连续可读 |
| 题面 | 22px/1.8；≤600px为20px | 公式、长材料与选项保持可读，实际用户字号调整需另行实现 |
| 模拟讲义文字 | 15px/2.1；≤600px为14px | 原件与界面控制区分，不能宣称真实PDF文字已解析 |
| 标签与表格 | 通常13px；辅助文字12px，部分页眉/脚注11px | 关键条件、错误及操作说明保持可辨认，不靠降低透明度制造层级 |
| 指标数字 | 29px；分钟预算49px/43px/39px，数字采用tabular-nums | 同时给出样本、单位和条件，数字不表示自动掌握或预测考分 |

字体大小属于当前原型实值，阅读能力验收仍需长文本、中英混排、公式和200%缩放。后续实装通过主题与用户字号偏好适配，不限制浏览器或思源整体缩放。

## 4. 空间与组件

当前原型以16–24px区块间隔组织内容；普通卡片内边距25px、中窄屏21px，阅读卡窄屏17px。卡片圆角18px、窄屏16px；输入与按钮11px，选项/提示12px，对话框20px。宽屏内容区上限1440px，主内容与辅助区24px间隔。首页重点区略抬升，普通卡片使用轻阴影，导航选中条与子导航下划线区分当前层级。

| 组件/场景 | 当前视觉表达与目标行为 |
|---|---|
| 主导航 / 全局项目入口 | 图标与名称并列，当前主域有背景及文字强调；设置保持全局入口 |
| 来源/条件/任务徽章 | 中性、accent、good、warn、bad五种语义类；配明确文本，不把“模型信心高”当正确性回执 |
| 题面与选项 | radio/checkbox与选项文字同一标签；选中用边框及背景，判分后配文字说明正确/需修正 |
| 保存反馈 / 警告区 | 已确认、失败、待恢复和模拟状态可区别；失败说明保留了什么及下一操作 |
| PDF/视频与个人笔记 | 原件区和可编辑笔记区各自有边界；显示页/时间点，原件可访问性与笔记保存分别表达 |
| AI输入与审核 | 输入预览、依据、待审产物、original/proposed差异和应用回执分层；批准前可拒绝或编辑 |
| 复习与四档自评 | Again/Hard/Good/Easy有文字含义，自评由用户选择；用时显示不自动提交或推断评级 |
| 严格模考 | 题面、答题卡、剩余时间和保存状态清楚可见；交卷确认与普通作答分开，AI入口显示暂停原因 |
| 证据报告 | 分母、样本、范围和帮助条件与数字同屏，7px条形显示对应示例指标；文本等价与证据下钻可达 |
| 知识资产/用途预览 | 含原件/仅指针/个人笔记各有身份；备份、迁移、分享和删除分别说明影响 |

进度条表示其明确标注的数量或比例。图表和状态不能把“看过”“即时答对”“受助正确”和“延迟独立正确”合成为一个无口径的掌握度值。成绩与AI建议分使用不同标签；rubric反馈遵循 [AI模板规范](18-AI智能体与提示词模板规范.md)。

## 5. 响应式与真实路由

原型实际媒体查询为1100px、960px、850px及600px；真实宿主按容器宽度另行实现，不能直接复制窗口断点：

| 宽度 | 当前CSS行为 |
|---|---|
| >1100px | 232px侧导航，主/辅区286px或reader辅助300px；侧栏可滚动 |
| ≤1100px | 200px侧导航，主/reader辅助248px，卡片与间距收紧 |
| ≤960px | 主/reader内容单列，辅助卡片暂为两列；不挤压主要题面/原件 |
| ≤850px | 导航改为有遮罩的抽屉，背景inert，键盘循环与Esc返回 |
| ≤600px | 表单/指标/辅助卡片单列，预算为两列紧凑区，题面20px，工具栏可换行 |

以上是原型CSS行为，平台接口能力按实际前端另行探测。页面宽度不决定文件选择、AI或模考是否永久可用；能力不足时显示原生/系统或手工路径。

路由由 [prototype.js](../design/prototype/prototype.js) 的titles/screens与hash处理定义。页面刷新可直接进入相应hash，未知ID回首页；严格模考进行时离开相关入口需处理会话条件。

## 6. 可访问性与动效

触控操作的目标命中区域至少44×44px。当前CSS将一般按钮、选择器/输入、导航/分段控件及答题卡按钮的最小高度统一为44px，一般按钮同时设44px最小宽度；复合标签、checkbox/radio、被局部样式覆盖的控件和实际命中区域仍需浏览器检查，不能仅由CSS声明推断全部达标。小radio/checkbox可以由完整标签提供可达区域；操作之间保持足够间隔。

正文/辅助文字对比度目标4.5:1，符合条件的大字3:1，必要控件边界与状态信息3:1。装饰分隔线与必要输入边界需要区分。按当前CSS实值计算的代表组合为：

| 前景/背景 | 浅色对比度 | 深色对比度 |
|---|---:|---:|
| text / surface | 13.66:1 | 13.66:1 |
| muted / surface | 5.30:1 | 7.42:1 |
| accent / surface | 6.05:1 | 8.14:1 |
| control-border / surface | 3.13:1 | 3.80:1 |
| green / green-bg | 5.18:1 | 7.67:1 |
| amber / amber-bg | 5.05:1 | 7.37:1 |
| red / red-bg | 4.95:1 | 6.76:1 |
| 主按钮文字 / accent | 6.10:1 | 8.39:1 |

这些结果只验证指定色值组合，没有覆盖禁用透明度、全部背景、实际思源主题和所有控件。原型以3px accent outline和3px偏移显示`:focus-visible`；必要焦点不能被粘性区域或弹窗遮住。跳到内容入口、表单标签、当前导航、dialog标题、状态播报和键盘返回需按真实焦点顺序检查；长材料、图表与表格保留文本可读路径。

当前动效仅在`prefers-reduced-motion: no-preference`下启用：按钮/选项背景、边框与阴影160ms过渡，真正切换场景时180ms淡入/3px入场。局部输入/状态刷新不重播页面入场。减少动效时保留静态状态变化；计时与保存结果仍清楚可见。视觉动效不能延迟作答、隐去错误或自动选择内核评级。forced-colors模式为卡片、选项、按钮和进度补系统颜色边界，实际可辨认性仍需检查。

## 7. 思源实装与验收边界

现有工程样式为 [lv-tokens.scss](../src/scss/lv-tokens.scss)和[lv-base.scss](../src/scss/lv-base.scss)。这些文件包含既有主题派生色、透明度及动效；本轮未修改或重新构建，不能认定它们已与本规范逐项一致。后续对选入场景使用b3控件及语义变量，必要fallback集中维护并核验，正文辅助色不机械采用固定低透明度。

评审使用本地原创数据，记录原型版本、所选场景、主题、宽度、键盘/触控与减少动效状态。实际产品另按 [docs/19](19-待办融合与分阶段执行规划.md) 选定范围验证资料打开、保存恢复、AI真实输入、模式/许可、计分、内核评级和宿主接口。颜色计算、路由存在或可点击演示均不能替代真实旅程验收。
