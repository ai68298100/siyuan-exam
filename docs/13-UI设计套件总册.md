## 3. 组件契约与复用原则

下列是设计责任名称，具体组件文件可随现有工程逐步调整，不要求先建全套公共组件。

| 组件责任 | 跨场景需要保持一致的行为 |
|---|---|
| 项目与目标栏 | 明确当前项目/题目/资料；目标变化刷新实际上下文及返回路径 |
| 来源与定位卡 | 出处、版本、页/时间点、许可及可访问性分别呈现；失效可以修复 |
| 保存反馈 | 草稿/保存中/已确认/失败/结果未知分别表达，失败保留内容 |
| 模式与帮助条件 | 独立/受助/已揭示/strictMock清楚可见，已开放入口执行同一条件 |
| 题面与答案输入 | 支持对应结构化答案；焦点、键盘、长材料与移动安全区一致 |
| 预览与差异 | 原始/候选、来源和目标revision可查；批准与应用回执分开 |
| AI输入摘要 | 显示实际片段、任务目的、通道、预算及缺项；正文与凭据分开 |
| AI任务状态 | 取消、部分成果、失败、迟到和未知执行均有可操作解释 |
| 证据卡与文本图表 | 标明范围、样本、分母和条件；缺失保留未知，点击保持范围 |
| 下一行动卡 | 说明证据、理由、预计成本与完成定义；允许改写、暂缓或拒绝 |
| 用途/导出预览 | 私人备份、迁移、打印、分享分别核对资源及传播范围 |
| 能力与联动卡 | 逐工具/前端/版本展示支持、降级、未验证和权限撤回状态 |

最小复用先覆盖一个任务产物与一个目标类型；命题、笔记、评分、计划和原件编辑保留各自的验收。AI解释、作者解析和用户反思使用相同的来源表达规则，但不能合并成一段没有身份的“标准答案”。

## 5. 本地原型的演示协议

原型使用原创讲义、模拟PDF页/视频片段及原创混合题型。导航、字段切换、作答、笔记和任务状态只在演示数据中发生；页面明确标识“设计原型/模拟”，刷新或重置说明模拟数据的生命周期。

当前可点演示包括15个路由、主题/状态切换、原创单选/多选、笔记输入、复测自评、导入步骤和候选接受/拒绝。17个`detailDialogs`入口仅打开目标交互说明，包含题目/候选编辑、外部打开、工具联动、规则影响、归档和导出等预览；关闭或取消回到当前场景，没有完整编辑器、真实工具调用、归档或文件生成。需要真实内容时继续使用思源个人笔记及手工定位，后续按所选产物验证对应能力。

任务取消仅修改模拟状态，“迟到结果”仅展示说明消息；本轮没有真实异步请求、AbortSignal、并发或迟到成果。它们可以评审状态文案，实际恢复与不误写目标仍需真实请求和回执验收。

演示可覆盖所选片段的AI输入预览、待审题、人工批准、提交后讲解、个人笔记及行动状态。模型回复、页码跳转、播放器、导入回执、严格模考计时、工具状态与保存成功均为模拟；对应控件不会打开真实系统程序、连接账号、请求模型或操作用户文件。

来源路径、许可证据和效果数字均采用原创示例。模拟的“已授权”状态只用于展示许可差异，不暗示商业题库可自由获取。小驴系列、思阅、思播、思盘和智能体以能力/降级示例表达；目标接口未实现时不展示为已接入事实。
