## 四、关键实现决策

1. **FSRS 全走内核**：调度/建卡/评级调 `/api/riff/*`（官方 API.md 未文档化，按内核源码调用，参考小驴卡盒调研已验证的 16 端点清单）；插件绝不自行持久化 FSRS 状态。前端用 ts-fsrs 仅做统计估算与预测。**与内置闪卡共存**（设计评审 #5.2）：题目卡全部落在独立卡包命名空间 `小驴考试/<题库>/<章节>`，与用户自建闪卡隔离；插件不写内核全局每日新卡上限；期望保留率是全局 FSRS 配置——设置面板醒目警示"将影响所有闪卡"，并提供"打开内核设置"跳转而非静默改写。
2. **题目渲染走内核 Lute**（设计评审 #4.3；R3 实测修正）：题目块 markdown 经 **`/api/lute/md2html`**（R3 实测：该端点存在，参数 `markdown`+`mode`；~~`/api/lute/md2BlockDOM`~~ 不存在）渲染为 HTML，放入 `b3-typography` 容器展示——公式/代码/图片与思源观感一致，零自研渲染器；渲染结果按块 hash 缓存。
3. **AI 共享任务与双向接入**（本轮重点架构候选）：模型访问优先复用思源内置配置，前提是思源 AI 已启用且可用模型已配置；高级用户可另配 OpenAI 兼容端点。现有两条模型通道共用 `AiChannel`，内核代理不代表本地模型或免费调用。另一个方向是经 `Plugin.addAgentCapability` 将本插件业务能力注册给思源智能体，由当前发起会话的前端执行 handler；注册返回能力 ID，不是模型端点或会话。统一工作台、就地入口与智能体入口计划复用同一任务、上下文、模板及提案/应用服务，覆盖导入、命题、练习、复盘、计划和知识写回，详见 [docs/18](18-AI智能体与提示词模板规范.md)。
4. **petal 同步策略**（设计评审 #5.1）：作答流水按 `月份.设备ID` 分片（多端并集互不覆盖）；错题本/会话/快照为本地缓存可重建；配置文件低频写入。作答落盘走会话批量（结束/切走/每 10 题/30 秒节流）。
5. **作答流水与块解耦**：删除题目块时流水保留（孤儿事件在重算器中忽略），重建块后按 `exam-id` 重新关联——防误删毁数据。
6. **导入容错**：逐题 try-catch，错误行收集为清单（行号/原因/原值）；"先导 5 行"试导入模式作为一等按钮。
7. **性能**：题库 SQL 检索全走内核（`/api/query`），前端只持当前会话的题目集；万题级题库的分页与虚拟滚动。
8. **图表**：热力图/雷达/趋势用轻量 SVG 自绘（对齐思源原生观感），不引 ECharts 全家桶；如复杂度超预期再评估。
9. **kernel.js 暂不引入**：无常驻服务需求；未来做"多端共享刷题会话/挑战码在线互认"时再评估 3.8 内核插件能力。
10. **上架**：release 含 `package.zip`（GitHub workflow 自行 zip dist，与"无 kernel.js"自洽）；集市走 fork bazaar + plugins.txt 一行 PR（有 siyuan-plugin-release skill 流水线）。
11. **测试策略**（R3）：判分器/导入解析器（Excel 字段映射、Aiken/GIFT 状态机、apkg 拆分）/掌握度公式是纯函数，进 vitest 单测（不依赖思源）；UI 层以 svelte-check + 手动冒烟清单（docs/11 每屏三态）覆盖。
12. **配置迁移**（R3）：settings JSON 携带 `schemaVersion` 字段，迁移器按版本链升级，旧字段保留兜底——模块开关与 AI 配置后续演进不动用户数据。
13. **日志与错误分类**：统一 `[lv-exam]` 前缀；区分可重试失败、需要修复的损坏/端点失效、用户取消，以及执行结果未知。网络或 AI 限流须先判断任务是否已执行、请求是否已计费；仅在可安全重试时提供重试，未知执行先查回执与目标版本。

### AI 接入、权限与模板的共同边界

接入按宿主版本、前端、模型、能力开关与权限探测。安装的 `siyuan@1.2.5` 已声明 `addAgentCapability`，官方 v3.8.0 已有该方法，v3.7.3 为旧 `addAgentAction`；新版调用链细节以 v3.8.6 固定源码为本轮研究基准，不能从旧端点表推定全版本兼容。类型与源码证据不代替真机生命周期、结构化输出、模型工具调用或多端验证。

能力按输入/输出 Schema 暴露有限业务动作，并如实声明 `effects`/`actionEffects` 的 `localRead/localWrite/dataEgress/externalCost`。宿主策略可禁用、强制确认或允许能力，会话许可也可能免确认；插件仍需核对用户选择、材料权限、目标 revision 和变更 diff，生成提案与应用分离。`localRead:true` 的工具返回值仍可能进入外部模型，返回摘要遵守与普通 AI 入口相同的最小化和外发范围。

前端能力随当前实例与 generation 执行，卸载时注销。浏览器能力没有自动内核快照；提交服务应自行设计幂等回执、版本检查和恢复范围。执行后超时、取消或输出校验失败可能产生 `ExecutionUnknown`，应先核对实际变更，禁止盲目自动重试。现有思源模型通道忽略 `AbortSignal`；停止后续步骤/写入与取消远端推理分别说明，已外发的数据和已产生的费用不能承诺撤回。

内置提示词按固定契约、任务正文、考试/学科叠层、用户偏好和结果 Schema 管理版本，完整设计见 [docs/18](18-AI智能体与提示词模板规范.md)。后续可封装为用户主动安装/更新的思源 `SKILL.md`，提供用途和能力选择指引；先预览版本、位置与同名冲突，不覆盖用户技能、全局指令或模型配置。技能指导不替代权限、判分、上下文裁剪和写入校验，本轮未注册能力、安装技能或替换运行时模板。

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| riff 端点未文档化、版本变动 | 封装层隔离（core/riff.ts 单文件收口）；启动探测版本，失败降级为"仅刷题不记忆" |
| 思源块属性写入量大导致同步慢 | 块属性最小化（元数据 <300B/题）；大题库建议独立笔记本 |
| Excel 各家格式千奇百怪 | 字段映射 UI + 净化规则 + 错误清单（调研 02 号实证的三大痛点全部产品化） |
| LLM 出题质量不稳定 | 原分片证据、字段校验、独立审题候选、人工 pending 审核与任务评测；历史 quality_score 设计不视为已实现或质量证明，AI 不可用仍保留资料/学习流程 |
| AI 端点可达但契约/权限不可用 | 区分端点可达、SDK/源码和真机验证；按版本/模型/前端/授权启用任务，保留手工流程 |
| AI 取消后仍有外发、费用或未知执行 | 展示取消实际范围；应用先核对回执/目标版本，幂等与恢复不依赖宿主自动快照 |
| TTS 平台差异（Windows/mac 语音） | 按句切分 + 引擎探测 + 静默降级为无声模式 |
| 功能面过宽导致臃肿 | 模块开关 + P0/P1/P2 分期（路线图）+ 验收口径约束 |

## 六、内核 API 实测记录（R3，2026-10-01，基于 sy 端点表 v3.7.3+）

## 附录 A：干扰项构建规范（Haladyna & Downing，1993 / TGM-D 复述版）

AI 出题（`buildPrompt` 注入 `HALADYNA_RULES`）与人工审题共用此规范；选择题逐条自查：

1. **同质性**：干扰项彼此同类（同概念域/量纲/表述长度），禁止唯一长选项或唯一精确表述。
2. **可诊断性**：每个干扰项对应一个可命名的常见误解（算错/偷换概念/张冠李戴），解析中点名该误区。
3. **无线索**：禁止绝对化词面（都/最/必然/一定）与题干词面重复造成的提示。
4. **无兜底**：不用"以上都对/都不是/全部/都不"及组合式选项。
5. **独立性**：选项互不重叠，单项只有一个可辩护正确答案；多选各正确项有独立依据。
6. **无位置偏好**：正确项的位置/长度不形成规律。

出处：Haladyna & Downing (1993) *How many options is enough?*；TGM-D（Taxonomy of Guideline Items 修订分类）。本插件落地：AI prompt 第 5 条硬规则 + 二遍审题人 prompt（`reviewQuestions`）核查干扰项合理性。
