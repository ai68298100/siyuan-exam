## 一、技术栈与工程

| 项 | 选择 | 依据 |
|---|---|---|
| 模板 | `siyuan-note/plugin-sample-vite-svelte`（Vite 8 + Svelte 5 + pnpm，Node ≥ 24） | skill 规范推荐；社区先例 Achuan-2/siyuan-plugin-copilot 同栈且符合思源设计语言 |
| 仓库名 | `siyuan-exam`（= plugin.json `name`，main 分支） | 集市上架硬性要求 |
| UI | 全部 b3 CSS 变量 + 内置组件类（`.b3-button/.b3-dialog/.b3-list/.b3-switch/.b3-slider`…），禁止硬编码色值 | 与主界面观感一致，亮暗主题自动适配 |
| i18n | `public/i18n/zh-CN.json` + `en.json`（≥ 双语） | 当前构建入口；实现阶段需加键集合校验 |
| 数据 | 题源=块；流水/派生目标为 `loadData/saveData` 分片方案 | 目录、同步覆盖、并发追加能力须先通过内核实机复核 |
| 依赖 | 规划使用 `sql.js`（apkg）、`xlsx`（Excel）、`ts-fsrs`（统计估算）、GIFT/Aiken 自研解析器 | 依赖尚未全部加入 package.json，落地前完成体积/许可证/离线评估 |

## 二、UI 形态（frontends: desktop + mobile）

| 形态 | 载体 | 内容 |
|---|---|---|
| 顶栏按钮 | `addTopBar` | 一键进入"今日任务"（每日一练/到期复习聚合） |
| Tab：练习台 | `addTab` | 单题快刷/专项树/整卷三栏入口 + 做题界面 |
| Tab：模考场 | 同上复用 | 组卷蓝图配置 → 全真模考界面（全屏专注模式） |
| Tab：报告中心 | 同上复用 | 四件套图表 |
| Dock：错题本 | `addDock`（桌面）/ 移动端入口收敛到 Tab | 错题列表（错因/消灭进度）、收藏 |
| 设置面板 | `openSetting` | 模块开关、FSRS 参数（保留率/每日上限）、AI 配置、导入模板下载、听学/无障碍 |
| 斜杆命令 | 菜单注入 | `/考试` 插入题目模板块（手工录题入口） |
| 块菜单 | 右键菜单 | "加入错题本/转为闪卡/加入练习集/标记考点" |
| 命令面板 | `addCommand` | 快速开刷、继续上次会话、开始模考 |

移动端原则：核心是"每日一练 10 题"完整流程（验收标准之一）；模考与批量导入仅桌面。

## 三、模块划分（src/ 结构）

```
src/
├── index.ts               # Plugin 入口：生命周期/UI 注入/模块开关路由
├── core/
│   ├── store.ts           # 题库读写：块 CRUD、块属性契约、SQL 检索（/kernel/api/query）
│   ├── attempts.ts        # 事件层：append-only JSONL、分片、重算器
│   ├── wrongbook.ts       # 错题派生视图
│   ├── mastery.ts         # 掌握度/留存率/预测（FSRS R 公式 + ts-fsrs）
│   └── riff.ts            # 内核 /api/riff/* 封装（建卡/到期/评级/卡包）
├── importer/
│   ├── pipeline.ts        # 映射→净化→校验→去重→预览→入库（统一漏斗）
│   ├── excel.ts / csv.ts  # xlsx 解析 + 模板列契约
│   ├── aiken.ts / gift.ts / tsv.ts
│   ├── apkg.ts            # sql.js 只读解析
│   └── template.ts        # 官方模板生成/下载
├── ui/
│   ├── practice/          # 练习台（做题/背题双模式组件）
│   ├── recite/            # 背诵模式（四级自评/提示链/计时）
│   ├── mock/              # 模考场（蓝图/计时/答题卡/成绩单）
│   ├── report/            # 图表（优先轻量自绘 SVG，避免重依赖）
│   ├── wrongbook/ import/ settings/
│   └── shared/            # 题目渲染器（题型×形态）、键盘导航、TTS 控制器
└── ai/
    ├── client.ts          # OpenAI 兼容端点抽象（BYO key，走内核代理或直连）
    ├── gen.ts             # 出题管线（切片→prompt→超量→校验→二遍→入库 pending）
    ├── explain.ts         # 讲解侧栏（逐选项/Hint/苏格拉底）
    └── prompts/           # Prompt 模板（内置预设，用户可编辑）
```

`public/i18n/zh-CN.json` 与 `public/i18n/en.json` 是当前实际的 i18n 资源路径。

> 上述 `core/`、`importer/`、`ai/`、`ui/shared/` 等为目标目录，不代表当前已经存在；当前源码仍是三个占位 Tab。实现任务和当前差距见 [docs/14-仓库审计与改进计划](14-仓库审计与改进计划.md)。

## 四、关键实现决策

1. **FSRS 全走内核**：调度/建卡/评级调 `/api/riff/*`（官方 API.md 未文档化，按内核源码调用，参考小驴卡盒调研已验证的 16 端点清单）；插件绝不自行持久化 FSRS 状态。前端用 ts-fsrs 仅做统计估算与预测。**与内置闪卡共存**（设计评审 #5.2）：题目卡全部落在独立卡包命名空间 `小驴考试/<题库>/<章节>`，与用户自建闪卡隔离；插件不写内核全局每日新卡上限；期望保留率是全局 FSRS 配置——设置面板醒目警示"将影响所有闪卡"，并提供"打开内核设置"跳转而非静默改写。
2. **题目渲染走内核 Lute**（设计评审 #4.3；R3 实测修正）：题目块 markdown 经 **`/api/lute/md2html`**（R3 实测：该端点存在，参数 `markdown`+`mode`；~~`/api/lute/md2BlockDOM`~~ 不存在）渲染为 HTML，放入 `b3-typography` 容器展示——公式/代码/图片与思源观感一致，零自研渲染器；渲染结果按块 hash 缓存。
3. **AI 双通道**（设计评审 #5.3）：默认复用思源内置 AI 配置（内核 `/api/ai/*`，用户零配置开箱即用）；高级用户可在插件设置另配 OpenAI 兼容端点与 key（独立模型/温度/批处理控制）。两通道同抽象接口，出题管线只认接口。远期经 `addAgentCapability` 把"给此笔记出题/讲解此题"注册为思源 Agent 能力。
4. **petal 同步策略**（设计评审 #5.1）：作答流水按 `月份.设备ID` 分片（多端并集互不覆盖）；错题本/会话/快照为本地缓存可重建；配置文件低频写入。作答落盘走会话批量（结束/切走/每 10 题/30 秒节流）。
5. **作答流水与块解耦**：删除题目块时流水保留（孤儿事件在重算器中忽略），重建块后按 `exam-id` 重新关联——防误删毁数据。
6. **导入容错**：逐题 try-catch，错误行收集为清单（行号/原因/原值）；"先导 5 行"试导入模式作为一等按钮。
7. **性能**：题库 SQL 检索全走内核（`/api/query`），前端只持当前会话的题目集；万题级题库的分页与虚拟滚动。
8. **图表**：热力图/雷达/趋势用轻量 SVG 自绘（对齐思源原生观感），不引 ECharts 全家桶；如复杂度超预期再评估。
9. **kernel.js 暂不引入**：无常驻服务需求；未来做"多端共享刷题会话/挑战码在线互认"时再评估 3.8 内核插件能力。
10. **上架**：release 含 `package.zip`（GitHub workflow 自行 zip dist，与"无 kernel.js"自洽）；集市走 fork bazaar + plugins.txt 一行 PR（有 siyuan-plugin-release skill 流水线）。
11. **测试策略**（R3）：判分器/导入解析器（Excel 字段映射、Aiken/GIFT 状态机、apkg 拆分）/掌握度公式是纯函数，进 vitest 单测（不依赖思源）；UI 层以 svelte-check + 手动冒烟清单（docs/11 每屏三态）覆盖。
12. **配置迁移**（R3）：settings JSON 携带 `schemaVersion` 字段，迁移器按版本链升级，旧字段保留兜底——模块开关与 AI 配置后续演进不动用户数据。
13. **日志与错误分类**（R3）：统一 `[lv-exam]` 前缀；错误二分类——可重试（网络/AI 限流，UI 提供重试按钮）与致命（数据损坏/端点失效，UI 引导到设置·数据重算或降级路径）。

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| riff 端点未文档化、版本变动 | 封装层隔离（core/riff.ts 单文件收口）；启动探测版本，失败降级为"仅刷题不记忆" |
| 思源块属性写入量大导致同步慢 | 块属性最小化（元数据 <300B/题）；大题库建议独立笔记本 |
| Excel 各家格式千奇百怪 | 字段映射 UI + 净化规则 + 错误清单（调研 02 号实证的三大痛点全部产品化） |
| LLM 出题质量不稳定 | 超量生成+二遍核验+quality_score 门槛+pending 审核流（06 号管线）；AI 永远不是题源依赖 |
| TTS 平台差异（Windows/mac 语音） | 按句切分 + 引擎探测 + 静默降级为无声模式 |
| 功能面过宽导致臃肿 | 模块开关 + P0/P1/P2 分期（路线图）+ 验收口径约束 |

## 六、内核 API 实测记录（R3，2026-10-01，基于 sy 端点表 v3.7.3+）

| 设计假设 | 实测结果 | 处置 |
|---|---|---|
| `/api/lute/md2BlockDOM` 用于题目渲染 | **不存在**。实际可用：`/api/lute/md2html`（markdown,mode）、`html2BlockDOM`、`spinBlockDOM`、`copyStdMarkdown` | 渲染决策改为 md2html（见决策 #2） |
| riff 端点 16 个 | **实测 17 个**：`addRiffCards`(blockIDs,deckID)、`createRiffDeck`、`getRiffDueCards`、`reviewRiffCard`(cardID,deckID,rating)、`skipReviewRiffCard`、`resetRiffCards`、`removeRiffCards`、`batchSetRiffCardsDueTime`、`getRiffCards(ByBlockIDs)`、`getNotebookRiff(Due)Cards`、`getTreeRiff(Due)Cards`、`getRiffDecks`、`removeRiffDeck`、`renameRiffDeck` | docs/02 端点名修正（createCards→addRiffCards）；skipReview 可用于 cram 跳题 |
| `/api/ai/chatGPT`（复用思源内置 AI） | **存在**（msg 参数），另有 `chatGPTWithAction` 与 3.8 全套 `/api/ai/agent/*`（chat/confirm/skills 等） | AI 双通道成立；agent 端点族为 addAgentCapability 预留 |
| 属性视图 API 成熟度（数据库承载题库视图候选） | **成熟**：`getAttributeView`、`addAttributeViewBlocks`、`addAttributeViewKey`、`batchSetAttributeViewBlockAttrs`、`appendAttributeViewDetachedBlocksWithValues` 等 15+ 端点 | 候选 #4 可行性确认，v0.2 排期评估 |
| `attributes` SQL 表（exam-fav 检索） | 内核当前离线未测；表存在性待复核 | docs/02 已标注兜底方案（遍历块 IAL） |

实测方法：`sy api -g`（端点表字节匹配查询）；SQL 与 md2html 调用因内核未运行待补测——实现 v0.1 前置任务里加"内核在线复核 attributes 表与 md2html 输出格式"一条。
