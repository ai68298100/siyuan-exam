# 小驴考试 · 仓库审计与改进计划

> 审计日期：2026-10-01。范围：`src/`、构建脚本、插件清单、i18n、设计/架构文档、原型和 `TODO.md`。本文件记录“设计承诺”和“可运行能力”的差距，作为实现阶段的基线；新增任务集中放在 [TODO.md](../TODO.md) 第 26 组。

## 一、结论先行

仓库的产品思路、数据模型、用户旅程和视觉规范已经完成了较充分的设计，但实际源码仍处于脚手架阶段。当前可以证明的是插件能被 TypeScript/Svelte 构建，不能证明用户能够导入题库、完成一次练习或得到错题报告。

这不是设计方向错误，而是交付顺序需要收敛。下一步应冻结大部分远期功能，先完成一条可重复验收的闭环：

> 新建题库 → 导入固定样例 → 生成题目块 → 进入会话 → 判分与反馈 → 写入作答流水 → 进入错题本 → 重练并消灭。

在这条闭环没有跑通前，模考、AI、游戏化和 TTS 都不应继续扩大实现面。

## 三、四条用户旅程的断点

1. **首次使用**：能打开练习台，但没有“新建题库”或真实导入向导，因此无法到达第一道题。
2. **日常刷题**：没有选题、会话、选项提交、判分、下一题、暂停或续做状态。
3. **考前冲刺**：没有到期队列、FSRS 调用、模考蓝图、计时、答题卡或结算。
4. **题库生产**：没有手工录题表单、导入映射、逐行错误清单、去重和题块写入。

这意味着当前产品体验停在“介绍页”，而不是“学习工具”。验收应从用户可完成的闭环计数，不能用占位页面数量衡量进度。

## 四、交互和 UI 审查

- `Practice/Mock/Report` 三个 Tab 仍是占位页；`Import` 和 `Blueprint` 按钮没有 `onclick`，会形成无反馈点击。
- 块菜单只注册“加入练习集”，点击后仅显示路线图 toast；i18n 中的“转为闪卡”和“标记考点”尚未注册。
- 错题 Dock 没有列表、筛选、跳转或消灭进度；移动端只有隐藏 Dock，没有浏览模式替代入口。
- 原型定义的 S1-S14、键盘流、加载/空/错误三态、会话续做、深链和设置分区都未进入源码。
- `sidebar-tabs-layout.svelte` 使用了 `role=tab`，但缺 `aria-controls`、`tabpanel` 关联、方向键/Home/End 导航和惰性挂载；隐藏面板仍会全部挂载。
- 三个 Tab 自己重复占位布局和内联宽度，`lv-base.scss` 的大部分组件尚未被消费；需要先建立 shared 组件契约，再按原型逐屏实现。
- 图标、按钮和卡片的键盘焦点、触控尺寸、`aria-label`、窄屏滚动策略和高对比主题仍需实测。

## 五、工程与数据风险

### 已发现的直接问题

- `index.ts` 把未绑定的 `onBlockIconClick` 传给 EventBus；回调上下文不由 API 契约保证，菜单点击可能丢失插件 `this`。本次审计已改为箭头属性。
- AI key 原先按普通文本输入；本次已让设置项声明 `password`，并让 `SettingUtils` 真正创建密码输入框。
- `SettingUtils` 的 slider/number 值会从数字漂移为字符串，number 没有变更回调；本次已统一转换有限数值、保存传入数据并补回调。范围校验、默认值恢复和 schema 迁移仍待实现。
- `dialog.ts` 使用字符串拼接和 `innerHTML` 写入 placeholder/defaultText/content；题干、导入文本或 AI 内容进入这些 API 时存在 HTML 注入风险。
- `PromiseLimitPool` 没有校验并发数，也没有取消、背压和大批量内存边界；异常任务与重复 `awaitAll` 的契约未定义。
- `tabApps` 按类型只保存一个实例；若同类 Tab 被多开，会覆盖引用并在销毁时卸载错误实例。应采用单例聚焦策略或按 Tab 实例管理。
- `docs/03` 规划的 `core/importer/ai/ui/shared` 目录和 i18n 路径与实际源码不一致；实现前要建立架构一致性检查。

### 构建和发布口径

- `pnpm check` 通过，`pnpm build` 的 app target 通过；这只覆盖编译和打包，不覆盖运行时行为。
- `VITE_BUILD_TARGET=kernel pnpm exec vite build` 当前因缺少 `src/kernel.ts` 失败，但 zip 插件会在失败前生成 `package.zip`，有产生伪产物的风险。必须删除死分支或补齐 kernel 入口，并让失败构建不留下可发布 zip。
- README/package scripts 宣称普通 `pnpm build` 会产出 `package.zip`，实际 app 构建只产出 `dist/`；release workflow 又自行 zip。需要统一一个发布命令和产物白名单。
- `.github` 目前只有 tag release workflow，没有 push/PR 的 check 门禁；仓库尚无测试目录、lint、覆盖率或 i18n 键校验。
- `plugin.json` 声明了桌面、移动、浏览器、Docker 等多端，但尚无能力探测和环境矩阵证据；声明应和实测结果同步。

## 六、建议的实现顺序

### P0：先把第一条闭环做成可用产品

1. 建立 `PluginContext`、模块注册表、生命周期 dispose、运行时能力探测和统一 `KernelApiClient`；所有 API 调用统一超时、取消、重试和错误码。
2. 先定 `Question/Attempt/Session/WrongItem/Review` 契约及 schema 版本，提供固定 fixture、迁移和损坏数据恢复策略。
3. 验证思源真实 API 与存储能力，再决定 JSONL 分片、写入锁、设备合并和目录布局；不能把未经实测的文件追加语义当作已成立的基础设施。
4. 完成 Excel/Aiken 最小导入漏斗（映射→净化→校验→去重→预览→逐题入库），为每行保留错误原因和可跳过结果。
5. 实现题块生成/读取、稳定 `exam-id`、题目渲染、单活动会话、判分、作答流水和错题派生视图。
6. 用真实 shared Svelte 组件替换三个占位 Tab，至少交付 S1/S2/S3/S9 的加载、空、错误态和移动端单列布局。
7. 让所有已有按钮都进入真实流程或给出可操作的禁用原因，清理“点击无反应”和无法关闭的错误状态。
8. 补 vitest 领域单测、内核 API mock/contract test 和一条可重复的 smoke flow；P0 以 fixture 结果验收，不以截图或页面数量验收。

### P1：闭环稳定后再扩展

先补 FSRS/错题状态机、背诵模式、模考计时与成绩单、报告数据源、双链深链、设置分区、ARIA Tabs、键盘/IME、响应式、错误边界、诊断导出和多端矩阵。每个模块都要先具备加载/空/错误三态和离线降级。

### P2：最后实现增强功能

AI 出题与讲解、题库包分享、TTS、游戏化、挑战码、站点发布和高级题型都建立在 P0 数据契约与可观测性之上。AI 仍需维持“用户主动调用、来源可追溯、待审核、可取消、可重试”的边界。

## 七、v0.1 纵切验收标准

使用仓库内固定的 5 行导入 fixture，以下流程必须在无 AI、可断网环境完成：

1. 首次进入显示新建/导入守卫；导入 5 行后显示成功数、跳过数和逐行错误。
2. 题目块含稳定 `exam-id`、题型、答案、来源和章节信息；刷新后仍能检索并渲染富文本。
3. 进入单活动练习会话，支持选择、提交、正确/错误反馈、下一题、暂停、恢复和退出确认。
4. 每次作答写入带唯一事件 ID 的流水；重复回放不会重复计数，损坏行会告警并继续重算。
5. 答错题目进入错题本，重练连对达到阈值后移出；刷新或重算后结果一致。
6. 390px 和 1280px 下均可完成上述流程；键盘与触控目标、焦点、错误提示和无题库空态均可达。

达到以上标准后，才把 v0.1 标记为“可用”；此前 README、截图和发布说明都应明确写“设计阶段/脚手架”。
