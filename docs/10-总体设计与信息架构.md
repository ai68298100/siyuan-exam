## 一、产品架构分层（自上而下五层）

```
┌──────────────────────────────────────────────────────────────┐
│ L4 表现层   顶栏(今日任务) · Tab(练习台/模考场/报告中心)        │
│             Dock(错题本) · 设置 · 块菜单 · 命令 · 斜杆          │
│             （远期：发布端答题页）                              │
├──────────────────────────────────────────────────────────────┤
│ L3 模块层   Module Registry：13 个功能模块按清单注册            │
│             模块 = {id, 开关, 依赖, surfaces 贡献, 生命周期}    │
├──────────────────────────────────────────────────────────────┤
│ L2 领域服务  题库引擎 · 练习引擎(会话) · 错题服务 · 记忆引擎     │
│             统计服务 · 导入服务 · AI 服务 · 计划服务 · 激励服务  │
├──────────────────────────────────────────────────────────────┤
│ L1 数据层   题源层(块+exam-*属性) · 事件层(流水分片)            │
│             派生层(缓存可重建) · 调度层(内核 riff/FSRS)         │
├──────────────────────────────────────────────────────────────┤
│ L0 平台层   思源内核：块/SQL/Lute 渲染/riff/AI/同步/发布        │
│             插件 API：Tab/Dock/菜单/事件总线/loadData          │
└──────────────────────────────────────────────────────────────┘
```

分层铁律：**L2 服务互相调用但不感知 UI；L3 模块只组装不实现；L4 界面只消费服务与注册表。** 未来任何新功能（题型/导入格式/练习模式/报告卡片）都是向注册表注册一个新条目，不动核心。

## 二、信息架构（IA）与导航地图

```
顶栏 ── 今日任务 ──────────────► 直接进入会话（到期复习+每日一练合并，零决策）
命令面板/快捷键 ── 同上三入口（⌥⌘P/M/R）

Tab 练习台 ─┬─ 刷题模式 ─┬─ 入口页（继续上次/今日任务/快刷/专项/整卷/错题/收藏/cram）
            │            └─ 会话视图（单题作答→反馈→结算）
            └─ 浏览模式 ─┬─ 左树（题库/章节/年份/标签）+ 右列表（过滤/搜索）
                         └─ 单题详情（题面 | 侧栏：统计/双链/AI/操作）
Tab 模考场 ──┬─ 模考列表（历史成绩曲线）
             ├─ 蓝图配置器（模块×题型×数量×分值×来源）
             └─ 全真模考（全屏：计时+答题卡）→ 成绩单
Tab 报告中心 ─ 总览（KPI 行+掌握度树+薄弱 Top10+热力图+分数预测）→ 下钻（知识点/题目）

Dock 错题本（桌面）── 消灭进度条 + 错题列表（错因/考点过滤）→ 点击进单题详情
设置面板 ── 通用 / 记忆 / AI / 导入 / 听学 / 激励 / 模块开关 / 数据
块菜单 ── 加入练习集 · 转为闪卡 · 标记考点 · 编辑题目 · 在练习台打开
斜杆 ── /考试（表单新建题目）· /圈题练习（查询嵌入块，v0.2）
```

导航原则：
1. **三跳内到任意题目**：任何列表/报告/统计 → 单题详情 →（编辑/转卡/跳笔记）。
2. **动作闭环**：每个列表都有"本视图开刷"；每个结算页都有下一步建议（错题回炉/继续专项）。
3. **移动端降级**：dock 收进浏览模式；蓝图配置器桌面限定；其余界面单列纵向复用。
4. **多题库并行**（R1）：题库=笔记本，可同时存在多个考试的题库；浏览模式顶部切换器切换，**今日任务跨题库聚合**（到期与每日配额合并计算，冲刺姿态只看考日最近的题库）。

| planner | 备考计划 | practice | ✅ | 今日任务、设置·考日 |

规则：禁用模块 → surfaces 不注册、命令不出现、依赖它的模块自动禁用；数据永远保留（开关只裁剪界面）。

### 3.2 注册表接口（TypeScript 契约）

```ts
interface ExamModule {
    id: ModuleId;
    displayNameKey: string;          // i18n 键
    defaultEnabled: boolean;
    dependsOn?: ModuleId[];
    surfaces: SurfaceContribution[]; // tab | dock | command | blockMenu | slash | setting
    onLoad?(ctx: PluginContext): void;
    onUnload?(): void;
}

interface PluginContext {
    services: ServiceRegistry;       // L2 领域服务句柄
    registries: {
        questionTypes: QuestionTypeRegistry;   // 见 3.3
        importAdapters: ImportAdapterRegistry;
        practiceModes: PracticeModeRegistry;
        reportCards: ReportCardRegistry;
        aiTasks: AITaskRegistry;
    };
    events: ExamEventBus;            // 模块间解耦通信
}
```

### 3.3 五大扩展注册表（未来空间所在）

| 注册表 | 条目契约（要点） | 已有条目 | 未来条目示例 |
|---|---|---|---|
| **题型 QuestionType** | `judge(作答输入)→判分`、渲染模板、属性 schema、导入字段映射、默认分值 | single/multiple/judge/fill/short/essay/match/material | 人机对话、完形填空、听力题（音频块+选项）、编程题 |
| **导入 ImportAdapter** | `match(文件特征)`、`parse()→标准化题目流`、字段映射模板 | Excel/CSV、Aiken、GIFT、TSV、Word、apkg、粘贴文本 | QTI 2.1、VCE、幕布/Notion 导出、幕课平台 CSV |
| **练习模式 PracticeMode** | `selectQuestions(题库,参数)→会话`、交互模板、记录 kind、入口卡片 | 快刷/专项/整卷/错题/收藏/cram/每日 | 挑战码 PK、间隔真题卷、错题变式卷（举一反三卷化） |
| **报告卡片 ReportCard** | 组件 + 数据依赖声明 + 时间粒度 | KPI/掌握度树/薄弱 Top10/热力图/分数预测/周报 | 模考曲线、考点对比、挑战赛战绩 |
| **AI 任务 AITask** | prompt 预设 + 输入类型 + 输出 schema + 校验器 | 出题/讲解/主观批改(v2)/考点打标(v1x)/口诀生成 | 真题风格迁移、错因归因分析 |

**模块间通信**只走 `ExamEventBus`（如 `session:ended`、`wrongbook:eliminated`、`ai:questions-pending`），禁止直接调用他模块内部——这既是解耦，也是将来"小驴复盘/打卡"跨插件联动的预留通道（eventBus 事件名带 `lv-exam:` 前缀可被其他插件监听）。

## 四、四大用户旅程（屏幕级串联）

### J1 首次使用（≈5 分钟到第一次刷题）
安装启用 → 引导对话框（三选一：**下载模板导入** / 斜杆手工录题 / **AI 从笔记出题**）→ 导入向导或表单 → 入口页"快速刷题"→ 会话 → 首个错题进本 → 引导打开 dock。
关键设计：未建任何题库时，练习台入口页显示引导卡片而非空态报错；**所有录入入口（块菜单/斜杆/导入）共享同一守卫**（R2）——无题库时先弹"新建题库"（一键建笔记本+章节骨架），落地后回到原动作。AI 通道未配置时同样给出两键引导（用思源内置 AI / 去设置）。

### J2 日常刷题（最高频，30 秒~10 分钟）
顶栏"今日任务"→ 直接进会话（到期复习优先+每日一练补足）→ 逐题作答（键盘流）→ 结算页（正确率/消灭数/连胜+1）→ 关闭即走。
关键设计：全程零决策——不问"练什么"，只答"练完了"。

### J3 考前冲刺（考前 2-6 周）
设置考日 → 冲刺姿态自动开启（顶部倒计时常驻）→ cram 队列（高频考点+错题≥2，不写回调度）→ 周末全真模考 → 成绩单三线对比 → 薄弱 Top10 定向再练 → 考后估分。
关键设计：所有冲刺界面右上角常驻"距考试 N 天"；考后一键恢复正常节奏。

### J4 题库生产者（老师/UP 主）
建题库笔记本 → Excel 批量导入（映射模板保存复用）→ AI 补解析/打考点 → 待审核队列逐题校对 → `.sy.zip` 题库包导出（含 changelog）→ 学生导入（保留作答历史的版本 diff）。
关键设计：生产侧与消费侧共用同一套题目块，无"导出格式"转换损耗。

## 五、核心状态机（引用与新增）

- **会话状态**：`idle → configuring → running ⇄ paused → submitting → settled`（每状态对应的 UI 形态见 docs/11 §S2/S6；`submitting` 只在模考存在，练习即答即记）。R2 压测补三条语义：**单活动会话**——同一时刻只有一个未完成练习会话，开新会话时提示"续做旧的/放弃并新开"；**过期草稿**——未完成会话 7 天后不再出现在"继续上次"，30 天自动清理（流水中的已答题记录保留）；**无题库守卫**——所有录入/练习入口在无题库时改为引导新建题库，而不是报错。
- **题目生命周期**：`draft(表单编辑中) → imported/ai-pending → verified → active ⇄ deprecated`；AI 题的 pending 审核流独立（docs/02 §五）。
- **掌握状态机**：docs/02 附录 A（错题本×形态×FSRS 三列联动表，唯一输入是 attempt 事件流）。
- **模块状态**：`enabled ⇄ disabled`（只裁剪 surfaces，数据与流水不受影响）。

## 七、设计原则重申（自上而下贯穿）

1. 题库进思源，派生可重建（数据主权）。
2. 一个调度器三种形态，用户只见"掌握度"（认知统一）。
3. 零决策开始，三跳内到任意题目（交互效率）。
4. 模块开关裁剪界面不裁剪数据（大杂烩不臃肿）。
5. 题型/导入/模式/卡片/AI 五张注册表（一切新功能=注册一个条目）。
